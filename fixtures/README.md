## 台账样本怎么脱敏的

**可复现方式**（不是手工改的）：

```bash
python tools/anonymize_ledger.py \
    "<源文件>.xlsx" \
    -o fixtures/case-ledger/ledger-sample-226.xlsx \
    --map artifacts/tmp/ledger-map.csv
```

替换规则（`tools/anonymize_ledger.py`）：

| 类型 | 规则 | 为什么这样 |
|---|---|---|
| IPv4 | 按首次出现顺序映射到 `10.0.<段>.<主机>` | **一一对应**：同一真实 IP 永远映射到同一假 IP，否则「A 端 ping B 端」这类跨列引用会断裂，导入后看不出结构对不对 |
| MAC | `02:00:00:00:00:NN` | 本地管理位（`02`）+ 顺序号，一眼看出是假值 |
| 账户名 | `user01` / `user02` … | 保留「这是个人类账户」语义，丢掉真实运维账号 |
| 序列号 | `SN-000001` … | 同上 |
| 版本号 | **不改** | `v0.2.6.0.1` 里的 `2.6.0.1` 形状像 IP，但前面是点 —— 已用 ASCII 边界排除，改错会破坏用例身份 |

**只导出「详细测试流程」一页。** 原表另含「当前测试环境」拓扑页（服务器 / BMC / 交换机 IP、型号、序列号、账户最密集的一页），导入链路用不到，直接不导出。

**自检**（脚本内置，失败即非零退出）：输出文件里凡匹配到 IP 的，必须全部落在 `10.0.0.0/16`；出现任何其它网段即判失败。2026-11-04 实测：782 处 IP 全为假值，账户残留 0，226 行 / 14 列 / 编号连续唯一。

> 映射表 `artifacts/tmp/ledger-map.csv` 是「假名 ↔ 真名」对照，**只能留在本机 `artifacts/`**（该目录已 gitignore）。不要复制到 `docs/` 或任何会被提交的位置。

## 台账样本与导入器表头差异（2026-11-04 定案：补别名）

脱敏做得再干净，也解决不了另一件事：**这份表的结构和导入器认的字段不是一套**。

`tools/check_import_header.py` 拿真实表头去撞 `CaseImportService.HEADER_ALIASES`（别名表从 Java 源码实时提取，不复制副本）。

**首次实测（补别名前）**：`列命中 1/14`，`[FAIL] 缺少必需列：用例编号（caseCode） / 标题（title）` —— `preview` 在 `CaseImportService:101` 直接抛错，一条都进不来。

**根因不是脱敏，是口径**：这份表是「带 A 端 / B 端命令、交换机配置的详细执行流程表」，而 ADR-0005 定义的台账是「编号 / 标题 / 分类 / 优先级 / 预置条件 / 步骤 / 预期 / 技术域」的文档态用例表。**两者不是同一个东西。**

三条路，大师选 **1（补别名）**：

1. ✅ **补别名**（已采纳）：把「测试编号 → caseCode」「测试用例 → title」「预置条件 → precondition」等加进 `HEADER_ALIASES`。能导进来，但命令类列**仍无处存放**，信息静默丢失 —— 大师明确接受此取舍。
2. ❌ 换 461 口径数据：找回字段口径匹配的历史台账。暂不走，这份 226 表同时用作安全分级样本（`tools/classify_cases.py`）。
3. ❌ 扩展用例模型：让台账能承载命令与步骤。属产品设计变更，要走评估 → PRD，不在补别名范围内。

**当前结果（2026-11-04 补别名后）**：`列命中 6/14`，`[PASS] 必需列齐，表头可定位`，退出码 0。

| 台账列 | 映射字段 | 结果 |
|---|---|---|
| 测试编号 | caseCode | 命中 |
| 一级分类 | category | 命中（**先出现的列赢**，见下） |
| 二级分类 | — | 未命中，忽略 |
| 测试用例 | title | 命中 |
| 测试类型 | category | 命中但**被丢弃**（`一级分类` 已在左侧占位） |
| 预置条件 | precondition | 命中 |
| 测试步骤（按序执行） | — | 未命中，忽略（命令类） |
| A端命令（设备见各用例预置条件） | — | 未命中，忽略（命令类） |
| B端命令（设备见各用例预置条件） | — | 未命中，忽略（命令类） |
| 交换机配置（按需） | — | 未命中，忽略（命令类） |
| 预期结果 | expected | 命中 |
| 执行状态与证据 | — | 未命中，忽略 |
| 当前环境适配 | — | 未命中，忽略 |
| 执行顺序 | — | 未命中，忽略（**不能**当 priority，见下） |

两个必须知道的副作用：

- **优先级全部落 P2**：台账没有优先级列，`Priority.from("")` 默认返回 `P2`，不报错。「执行顺序」那列是自然语言（"第二优先：其余70项"），映射到 `priority` 会让 `Priority.from` 抛「非法优先级」把 226 行全判错 —— 所以它是**故意不映射**的。
- **`测试类型` 被静默丢弃**：它和 `一级分类` 都映射到 `category`，Java 侧用 `containsKey` 判重、先出现的列赢，故取「一级分类」（"基本功能测试"）舍「测试类型」（"功能"）。语义上「一级分类」粒度更合适，属有意为之；工具会对此打 `[WARN] 多列映射到同一字段`，别当成没事。

工具本身也修过一个假红缺陷：原正则 `alias\(...\)` 跨不过 `//` 注释，导致夹了注释的 `alias("caseCode", …, "测试编号")` 整条被丢弃，别名统计错报成「30 个别名 / 8 个字段」（正确是 36/9），据此得出的「caseCode 认不出来」结论是假的。现改为**先剥注释再解析**，并加了「调用点数量 == 解析条数」的自检，漏抓直接非零退出。

`ENV-04` 因此可结。`CAS-03`（preview 读 N 行 0 错误）**已于 2026-11-04 真跑通过**，不是靠静态对账推的：
`CaseImportIT`（`@Tag("it")`，连真库 `robot_it`）实测 `preview totalRows=226 validRows=226 errors=0`，
`commit imported=226`，重导 `validRows=0 errors=226`。证据 `docs/evidence/v0.2/cas03-import-it.log`。
**静态对账 PASS 只能说明表头认得出，不能替代这一步** —— 之前正是因为只做了静态对账，
「461 条导入」才在 `待验` 上挂了三天。

## 增删规矩

1. 新增样本先问：**这真的是测试输入，还是产品数据？** 产品数据不该进 `fixtures/`。
2. 含真实设备信息的一律走 `tools/anonymize_ledger.py` 或等价脚本，**不接受手工替换**（手工替换无法自检、无法复现）。
3. 每个新目录要有一个 README 或在本表登记一行，写清「谁用它、验什么」。
4. 台账样本的**条数口径未定**（计划书原写 461，在手样本 226），所以 226 只作链路验证，**不得据此把 CAS-03 置 `已完成`**。
