# 端口矩阵（ENVX-02 / FR-v2.0-54）

> 三处一致：**系统设置页**（`entry.port` 只读）、**关于页**（端口矩阵段）、**本手册**。
> 改端口必须同时改 `application.yml` / `serve-entry.mjs` / `deploy.sh` / 本文 / 设置页与关于页的取值，
> 否则会出现「页面显示 8001、实际跑在别的端口」这类最难查的假故障。

| 端口 | 角色 | 进程 | 谁访问 | 健康检查 |
|---:|---|---|---|---|
| **8001** | **统一入口** | `node scripts/serve-entry.mjs` | 用户浏览器、打印链路 | `/healthz`（存活，不查库） |
| 8081 | 后端 API | Spring Boot jar | 仅 8001 反代，不直接对外 | `/api/health`（就绪，SELECT 1） |
| 5173 | 前端开发服务 | `vite dev`（仅开发期） | 开发者本机 | — |

## 8001 做什么

- 静态托管 `frontend/dist`；`index.html` 一律 `Cache-Control: no-cache`；带 Vite 指纹的资源 `immutable` 长缓存。
- SPA fallback：`/settings`、`/reports/RUN-001` 这类深链接刷新回 `index.html`，不返回 404。
- `/api/**` 反代到 8081（原样转发 method / body / headers）；`/ws**` 反代并透传 WebSocket 升级帧。
- `/healthz` 由入口自己应答，**不查库**：数据库抖动不该触发入口重启。

## 缓存与探针实测命令

```bash
curl -fsS --noproxy '*' http://127.0.0.1:8001/healthz
curl -fsS --noproxy '*' http://127.0.0.1:8001/api/health
curl -sI --noproxy '*' http://127.0.0.1:8001/                 # index.html → no-cache
curl -s -o /dev/null -w '%{http_code}\n' --noproxy '*' http://127.0.0.1:8001/settings   # 200（SPA fallback）
curl -sI --noproxy '*' http://127.0.0.1:8001/assets/index-XXXX.js   # immutable
```

## 部署、回滚与 TLS

- 一条命令部署并自检：`bash scripts/deploy.sh`（`--no-serve` 只构建）。
- 代码回滚：`bash scripts/rollback.sh --to <版本> --yes`（HRD-04 三步：备份 → 停服换产物 → 起服自检）。
- 入口进程由 `var/entry.pid` 管理；手工停：`kill "$(cat var/entry.pid)"`。
- 生产 TLS 样例：`deploy/nginx-8001.conf.example`（证书自备，本仓库不代签、不内置密钥）；
  systemd unit 样例：`deploy/robot-autotest-entry.service`。

## 报告打印基址

- 开发态：`report.export.print-base-url` 默认 `http://127.0.0.1:5173`。
- 生产态：由部署环境把 `REPORT_PRINT_BASE_URL` 指向 `http://127.0.0.1:8001`，
  打印 URL 一律走统一入口，不直连 8081。
