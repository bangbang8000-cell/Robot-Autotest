# UX-04b 第六批：套件树迁 `StatusTag` + 补齐交互三态 + 守门扫描范围扩大

日期：2026-11-05 ｜ WBS：`#80`（`UX-04b` 视图组件化迁移）｜ 复现：`bash docs/evidence/v0.3/ux04b5-20261105/run-all.sh`

## 1. 这批做了什么

报告详情页的套件树（`SuiteTree` / `KeywordSteps`）是全站最后一处「状态只有颜色 + 交互无三态」的地方。

| 位置 | 迁移前 | 迁移后 |
|---|---|---|
| 套件行状态 | `<span class="badge verdict-*">` 只有颜色 | `StatusTag`（图标 + 文字，`verdictTone`） |
| 用例行状态 | 同上 | `StatusTag` |
| 套件/用例的展开整行 `.tree-toggle` | 裸 `<button>`，**hover / focus-visible / transition 一个都没有** | 保留原生元素，**补齐三态 + 圆角 hover 底** |
| 关键字步骤行状态 | `.badge` | **刻意不动**（见 §2 第 2 条） |
| `tools/check_states.py` | 只扫 `styles/*.css` | 同时扫所有 `.vue` 的 `<style>`，并把 `.tree-toggle` 登记进 `REQUIRED` |

视图+组件级回归 **43 → 51**（8 个 spec，本批新增 `SuiteTree.spec.ts` 8 条），前端全量 **96 → 104**。

## 2. 四个判断，都写了理由

1. **没有用 `NButton` 换掉树行按钮 —— 这会用密度换"统一"。**
   库按钮 `--n-height` 最小档 28px（medium 34px），而这里的行高是 21px。一个套件里几十条用例，
   换成库按钮等于整棵树凭空高出一倍。而这行本质是**展开/收起控件**（disclosure），
   不是设计系统意义上的"按钮"：它没有按钮的语义（不改状态、不提交），只有"切一个布尔"。
   所以按**症状**修：缺的是三态，不是缺库组件 —— 给原生 `button` 补 `:hover` /
   `:focus-visible` / `transition`，密度一分不动。

2. **关键字步骤行保留紧凑文本徽标。**
   一屏可能排出几十行步骤，每行再加一个 16px 图标会把「步骤名」挤成次要信息；而这里
   状态文字本身就写在徽标里，颜色只是辅助，不存在「只有颜色读不出状态」的问题。
   `.badge` / `.verdict-*` 自此只有本组件一个消费者，全局样式保留并在注释里写明。

3. **守门扫描范围从"按目录"改成"按文件类型"。**
   这才是本批真正的根因修复。`check_states.py` 原来只读 `styles/*.css`，于是
   **组件 `<style scoped>` 里的交互元素天生在盲区** —— `.tree-toggle` 三态全无，守门却一直是绿的。
   现在同时抽 `.vue` 的 `<style>` 块（`MIN_VUE_STYLE_FILES = 5` 兜底，抽取失效就报错而不是静默变绿）。

4. **扩范围必须配一条能被证伪的证据。**
   「扫描范围变大了」这件事本身没有任何可观测产出：如果新扫描没生效，结果依然是 PASS，
   和扩之前长得一模一样。所以加了 `neg-tree-toggle.py` —— 把 `.tree-toggle:hover` 换成
   一个没人引用的选择器，新扫描必须报 FAIL。实测输出：
   `命中: .tree-toggle 缺 :hover 反馈` → `[OK] 负向自检通过`。

## 3. 一个方法论结论（写进 §3.2b）

> **"守门是绿的"只说明"守门扫过的地方没问题"，不说明"没问题"。**
> 判定盲区有两种来源：① 规则没登记；② **根本没扫到那个文件**。第二种更危险，
> 因为它不会随缺陷数量增加而变红，也不会被负向自检发现（自检注入的是"已扫到"的文件）。
> 发现盲区的办法不是读守门代码，而是**问"这类东西还可能写在哪些文件里"**。

本次就是这样发现的：报告页树行聚焦时看不出焦点 → 去查守门 → 守门只扫 `styles/` →
组件 scoped 样式从来没被扫过 → 顺着查出 `MIN_RULES=120` 是"只统计全局 CSS"的口径。
