## 关键设计取舍

1. **`null` 不渲染成空白**：`deviceScope` 为 `null` 的语义是「提交时未声明，执行期不做设备互斥」，
   与「字段丢了」是两件事。列表写「全部设备」，拓扑里写「未连接」，都是把**未知与确实没有**
   压成同一句人话，避免被读成渲染失败。
2. **先按设备聚合，再串成链**：同一台设备会在多条链路里重复出现。2026-11-06 之前是一条链路
   一行（问「这条链路两端是谁」够用），但 DUT → SW → HOST 这种三跳会被画成三张互不相干的图；
   现在按设备 id 建邻接表，把相邻链路串成一条链，一次画完一条通路。分叉与环不做特殊处理：
   走到不能再走就收尾，剩下的边由外层循环另起一行，保证「每条链路恰好渲染一次」。
3. **不引图库**：链路是两端关系，串成链后仍是**线性结构**，`grid` 按链长内联生成列就够了
   （节点 `minmax(0, 1fr)` 拉伸、边固定 180px，比容器宽时横向滚动）。引力导向图会带来布局抖动
   与可访问性问题，且当前数据模型没有节点表，画不出比链式更多的信息。
4. **切换视图清空勾选**：拓扑里没有复选框，留着旧选择会让批量动作带着看不见的行去发请求。
5. **拓扑不参与批量操作**：拓扑是只读视图，批量删除/执行仍回表格视图做。

### 关键取舍

1. **端点是设备而不是「链路侧」**：用 `d:<deviceId>` 做键才能把共用同一台交换机的两条链路接起来；
   没有登记设备的端点用 `u:<linkId>:<side>` 兜底，否则两条孤儿链路的「未连接」会被并成一个节点。
2. **分叉不特殊处理**：从 A 出发一次只能走一条路，剩余支路由外层 `for` 另起一行。
   代价是一条物理通路可能被拆成两行，收益是**不丢边**——这比「图好看」重要，丢边会让人误判没有连接。
3. **环会首尾各出现一次**：环上走一圈回到起点，`nodes` 首尾同键（渲染时 `:key` 用链内下标，
   不会冲突）。视觉上能看出闭环，不需要额外的环检测。
4. **不重排链路顺序**：链的顺序由 `links` 原顺序决定，翻页/筛选变化时不会跳动。
