## 4. 实测踩到的两个坑（留痕）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 回写脚本**重跑后 5 处又 PASS**，文档出现重复追加 | 5 处属「追加型替换」：`new` 里保留了 `old`，导致 `repl()` 的「old 仍在 → 再替换」判断成立 | 在 `repl()` 加通用检测：`old in new` 时取增量 `delta = new.replace(old,"",1)`，`delta` 已在文件中即 SKIP。修后**首跑 PASS=19 / 重跑 SKIP=19**；六份文档先 `git checkout --` 恢复再重跑，消除重复 |
| 2 | `sed -n "${n}p"` / `for x in ...; do tail "$x.md"` 打印全文或报 `.md: No such file` | Git Bash 调 `wsl.exe bash -lc` 时，双引号里的 `$var` 被外层吞掉，传到 WSL 已为空 | 不再用 shell 变量：直写固定行号、或用 `tail -n 6 file1 file2 file3` 多文件形式；回写逻辑一律放 Python 脚本 |

> 第 1 个坑与 P0-1 的「短前缀命中 2 行」同类：**文档补丁必须自带幂等与命中次数断言**，
> 否则重跑一次就悄悄污染文档。
