## 2. G2-4：弱口令与会话续期（缺口已补）

### 2.1 改动前的核实结论

`AuthService` 原实现只有 `touch()`，命中 SQL 是 `UPDATE api_token SET last_used_at = ?`，
**不延长 `expires_at`**；`AuthController` 只有 `login/logout/me`，**没有续期端点**。
即 FR-v0.2-04「会话过期前 5 分钟自动续」此前并未实现。

### 2.2 本轮实现（最小闭环）

| 层 | 位置 | 行为 |
|---|---|---|
| 仓储接口 | `application/repository/SessionTokenRepository.java` | 新增 `extend(tokenHash, expiresAt, usedAt)` |
| 仓储实现 | `infrastructure/SessionTokenRepositoryJdbc.java` | `UPDATE api_token SET expires_at=?, last_used_at=? WHERE token_hash=? AND token_kind='session' AND revoked_at IS NULL` |
| 应用服务 | `application/iam/AuthService.java` | `renew(token)`：SHA-256 → `findValidUserId` 校验 → `now + SESSION_TTL(8h)` → `extend`；无效/空令牌抛 `UNAUTHENTICATED`「会话已过期，请重新登录」 |
| 接口 | `api/iam/AuthController.java` | `POST /api/auth/renew` → `{ expiresAt }`（令牌取自 `AuthInterceptor.ATTR_TOKEN`） |
| 前端 API | `frontend/src/api/iam.ts` | `authApi.renew()` |
| 前端状态 | `frontend/src/stores/auth.ts` | 持久化 `auth_expires_at`；`armRenewal()` 在过期前 5 分钟 `setTimeout`；成功回写过期时间并重排，失败 `clear()`；`loadMe()` 成功后重排（刷新页面不丢定时） |
| 测试 | `backend/src/test/java/com/qa/autotest/application/iam/AuthServiceRenewTest.java` | **3 条**：有效令牌续期成功（断言 `extend` 入参）/ 无效令牌拒绝 / 空令牌直接拒绝 |

弱口令侧无需改动：`UserService` 建用户（`line 68`）与重置口令（`line 105`）都调用
`PasswordPolicy.validate(...)`，`PasswordPolicyTest` 5 条既绿。
