# CAS-02 前端补齐：用例集管理页（2026-11-06）

## 背景

WBS #17 一直记着「用例集前端页面未做（仅后端 API）」：`/api/v1/projects/{id}/case-sets` 的
列表 / 新建 / 改名 / 删除 / 成员增删 / 排序 / 立即执行全部可用，但界面上没有任何入口，
用户只能在执行计划的用例集下拉里间接看到集合，无法维护。本次把这一页补齐。

## 关键设计取舍

1. **不新增一级菜单**：`navigation.spec.ts` 明确「只有多个子页才立分组」，把「用例」改成
   分组会牵动导航测试与既有路径。选择 `/cases/sets` 作为子路由，`/cases` 叶子靠前缀匹配
   保持高亮。
2. **候选用例走服务端搜索**（300ms 防抖、每次 50 条）：台账可能上千条，一次性全量既慢又占内存；
   只做本地过滤会让用户误以为「搜不到就是不存在」。
3. **排序提交完整成员列表**：后端 `PUT /order` 要求 `caseIds` 覆盖当前全部成员，只提交被移动的
   一条会被拒绝。前端先在本地交换再整体提交，失败时回滚重拉。
4. **成员重复加入依赖后端 409**：不在前端做去重缓存，避免多标签页并发时前端状态过期。
