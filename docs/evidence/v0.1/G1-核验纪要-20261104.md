## 3. 现场新发现：`RUN_ID` 并发唯一性概率碰撞（必须留痕，不作假绿）

**现象**：`mvn -B test` 466 项中 1 项失败 ——
`RunIdGeneratorTest.并发不重复:34 expected: <1000> but was: <999>`；`ci-local` 三关因此 **exit 2**。

**根因**：`RunIdGenerator.next()` 末段为 3 字节 `SecureRandom`（2²⁴ = 16,777,216 种），
测试用**同一固定时间戳**连生成 1000 次，生日碰撞概率
`1 - exp(-1000×999 / (2×2²⁴)) ≈ 2.9%`。今晚第一次全量跑正好命中。

**复跑验证**：单独 `mvn -B -Dtest=RunIdGeneratorTest test` 连续 **6 次全部 exit 0（2/2）**，
确认是概率性 flaky，不是稳定缺陷。但**不能因此当作没问题**：

- `RUN_ID` 是三方关联唯一键（robotdashboard `runs.metadata` / `tools/link.py` 反查），
  同一秒内高并发时**没有硬唯一保障**，碰撞会串数据；
- 该用例本身用随机量做精确计数断言，属「用概率验证唯一性」，测试设计也不成立。

**大师裁决**：**记偏差 + 单开包修（不承诺工期）**，G1 判过但不作假绿。
→ 落为 WBS **#77 / EXE-09**，见 `docs/plan/WBS-STATUS.md` 与 `docs/release/README.md` v2.3。

## 3.1 现场第二个真发现：`db-undo.sh` 无法完成回滚（G1 #4 字面项未复现）

**现象**：按清单补跑 `DB_NAME=robot_it bash scripts/db-undo.sh` → **exit 1**，
`ERROR 1046 (3D000) at line 13: No database selected`（执行 `V7_3__asset_pool.down.sql` 时）。
随后 `db-migrate.sh` exit 0、`flyway_schema_history` 19 行、业务表 46 —— 但那只是**把本来完整的库重跑一遍**，
不构成「down→up」验证。

**根因**：`scripts/db-undo.sh:17` 用 `db_exec < "$f"`，而 `db-common.sh` 的 `db_exec`
不带库名参数（`--batch --skip-column-names "$@"`），down SQL 里也没有 `USE`。
只要客户端未默认选中库，回滚必然报 1046。属**脚本缺陷**，与 Flyway 迁移能力本身无关
（迁移侧 `SchemaIT` 7/7、IT 21/21 已通过）。

**处置**：**未擅自改脚本**（验收现场不动产品代码，大师也未授权此项开发）。
已把原始输出留在 `docs/evidence/v0.1/flyway-downup-20261104-2005.log`，
`robot_it` 走查前后均有备份、库结构未被破坏（`ROBOT_DEV_UNCHANGED=YES`）。
大师需定：并入 WBS #77 一并修 / 另开整改包 / 记为已知偏差 G1 照过。

**第四处「测试在给错误写法背书」**：修完 down 脚本后全量单测 466 项唯一红灯是
`MigrationFileTest.报告字段`——它硬断言 down 必须含 `DROP COLUMN IF EXISTS`，而这正是 1064 的根因。
已改为「直接 DROP 必须存在」+「SQL 行不得出现条件化 DROP（忽略注释行）」双向守门，重跑 **466/466**。
这类红不是回归，是把过时规范从测试里清掉；但**若当时为了「全绿」把 SQL 改回去，就会把 1064 重新埋回去**。

**修复的三处真缺陷**（都是「手写回滚脚本从未端到端跑过」暴露的，不是环境问题）：

1. `scripts/db-undo.sh` 用 `db_exec < "$f"` 连库但未选库，down SQL 全是裸表名 → `ERROR 1046 No database selected`。
   改为 `db_exec "$DB_NAME" < "$f"`，并加与 `db-reset.sh` 一致的 `_it` 安全阀；负向验证用 `DB_NAME=robot_dev` 实测被拒。
2. `V5_1 / V5_3 / V5_4 / V5_5` 四个 down 脚本共 **24 处** `DROP COLUMN IF EXISTS`，目标库不支持 → `ERROR 1064`。
   统一改为直接 `DROP COLUMN`（标准回滚序列里列必存在，db-undo 本就非幂等），脚本头留兼容性注释。
3. `V2_1__iam_fields.down.sql` 删 `idx_project_member_user` 时被外键 `fk_project_member_user` 依赖 → `ERROR 1553`。
   改为「先摘外键 → 删索引 → 挂回外键」。
   另修 `V7_1__audit_summary.down.sql` 同类条件化 DROP（1 处）。
