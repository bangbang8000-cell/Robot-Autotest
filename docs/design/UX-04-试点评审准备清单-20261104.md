### 0.1 被推翻的假设（按流程 ⑦ 留修订记录，不悄悄改字）

v1.0 把 §2.2 步骤 0 的**验收栏**「试点评审通过后本表后续步骤才开工」读成了
「评审通过后才做两页试点」。但同一行的**产出栏**写的是「试点分支 + 对比报告」，
`§3.2 TC-S1-00` 也要求「两个候选库各接登录页+用例页……产出试点对比报告」。
**没有试点实物，评审就没有对象** —— 原结论在逻辑上自相矛盾，v1.0 §4 自己也写了
「两套试点实现、对比报告、体积实测数需开工试点才有」。

**另一处口径变更**：v1.0 §2 写「试点走独立分支，不合并进 main」。本轮改为
**隔离目录 `docs/design/pilot/` + 不参与主仓构建**：源码入库便于评审与复现，
但依赖只装在该目录、主仓 `frontend/` 的 `package.json` / 视图 / 样式 / 路由一个都没动，
隔离效果与独立分支等价，且免去双远程（群晖 + GitHub）下的分支同步成本。
若评审要求改回独立分支，可整目录迁出，不影响任何主仓文件。

**没有改变的部分**：引库必须先做两页试点、不许直接全量重写（调研报告 §7）；
**人工观感判据始终只能由人给**（0.2 免除的是「评审会」，不是「人看」）。

### 0.2 闸门解除（v1.2，2026-11-05 00:20）

**决定**：不组织试点评审，直接开工。选型由学徒按试点实测数据定，依据写进
`UX-04-两页试点对比报告-20261104.md` §0.2，**不是「我觉得 Naive UI 好」**：
同两页同口径 gzip 154,779 B 对 174,484 B；主题对象不引入第二套 CSS 真源；
`GlobalThemeOverrides` 可由 semantic token 单向派生（试点已机检验证）。
选型可推翻——适配层是**单向派生**，换库只改 `naiveTheme.ts` 一个文件。

**解除后的落地范围**（主仓 `frontend/`）：§2.2 步骤 1~8 全部落程序骨架，
证据 `docs/evidence/v0.3/ux04-s1-20261104/`。

**没有解除的部分**：
- 人工观感判据（四态截图取色比对、1440/1920 表格观感、chunk 预算数值定夺）**仍需人看**，
  机检只能证明「没写错」，不能证明「好看」；
- 13 个业务视图的组件化迁移**不在本包**，已拆为 WBS #80 `UX-04b`。
  本包交付物是「骨架 + 局部替换」，业务页主体仍是原生元素——这点写在这里，防止后续
  有人看到 `UX-04` 是 `待验` 就以为页面已经全量组件化。

## 2. 试点范围（两页 × 两候选）

| 页面 | 为什么选它 | 覆盖的难点 |
|---|---|---|
| 登录页 | 页面小、无数据依赖，能最快验证表单组件与暗色 | Input / Button / 表单校验提示 / 亮暗两态还原度 |
| 用例页 | 结构最复杂、10 列宽表与批量动作 | 表格密度 / 分页 / 下拉 / 批量条与勾选态 / token 对接成本 |

| 候选 | 定位 | 已产出的对照物 |
|---|---|---|
| **Naive UI** 2.45.3（第一候选） | CSS 变量主题定制与暗色能力强、tree-shake 好 | 两页一版，`NConfigProvider :theme-overrides` 由 semantic token 单向派生 |
| **Element Plus** 2.14.7（对照） | 生态大、表格能力强 | 两页一版，`--el-*` 由 semantic token 单向派生 |

隔离方式见 §0.1；`src/theme.css` 直接从主仓复制，试点不另写一份色值。

## 3. 四个评审维度与判据

| 维度 | 判据 | 本轮状态 |
|---|---|---|
| 暗色还原度 | 中/英 × 亮/暗四张截图，取色比对 `--bg/--panel/--text/--accent`，色差在 `check_contrast.py` 阈值内 | ⏳ 取色链路已闭合，**四态截图待现场采集** |
| 与 semantic token 的对接成本 | 单向派生、试点内 0 硬编码色值、改动文件数写进报告 | ✅ `check_pilot.py` PASS（6 文件 / 24 token / 两版单向），`--self-test` PASS |
| 产物体积 | 组件库 chunk 实测 gzip；**预算在试点后由评审定**，不先验拍数字 | ✅ 实测表已出（Naive ≈151 KiB、Element ≈170 KiB gzip），**预算仍待评审定** |
| 表格密度可控性 | 10 列在 1440/1920 下：行高、粘性表头、只在表容器内横滚 | ⏳ 代码层能力已具备且无硬阻塞，**两宽度截图待现场** |

详细数据、限定条件与「不是净增量」等三条读法见《两页试点对比报告》§2，此处不重复。

评审结论只能由大师给出，四种结果：① Naive UI 通过；② Element Plus 通过；③ 两版都不达标 → 回退自建方案
（原 v1.0 §2.2 保留为回退路径）；④ 补充试点后再评。
