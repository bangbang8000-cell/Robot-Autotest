## 2. 试点范围（两页 × 两候选）

| 页面 | 为什么选它 | 覆盖的难点 |
|---|---|---|
| `LoginView.vue` | 页面小、无数据依赖，能最快验证表单组件与暗色 | Input / Button / 表单校验提示 / 亮暗两态还原度 |
| `CasesView.vue` | 结构最复杂、已有 10 列宽表与批量六动作 | 表格密度 / 分页 / 下拉 / 批量条与勾选态 / token 对接成本 |

| 候选 | 定位 | 需要产出的对照物 |
|---|---|---|
| **Naive UI**（第一候选） | CSS 变量主题定制与暗色能力强、tree-shake 好 | 两页各一版，主题变量由现有 semantic token 单向派生 |
| **Element Plus**（对照） | 生态大、表格能力强 | 两页各一版，同样的派生口径 |

试点走**独立分支**，不合并进 main；评审通过后才把选中的一版并入 v0.3 开发分支。

## 3. 四个评审维度与可量化判据

| 维度 | 判据（可机检 / 可复现） | 采集命令 |
|---|---|---|
| 暗色还原度 | 中/英 × 亮/暗四张截图，取色比对 `--bg / --panel / --text / --accent`，色差在既有 `check_contrast.py` 阈值内 | `python tools/check_contrast.py`（现有，UX-01b 已修 40 组） |
| 与 semantic token 的对接成本 | 库主题变量必须**单向由 token 派生**；试点分支内不得出现硬编码色值；改动文件数写进对比报告 | `python tools/check_tokens.py` + 逐个 diff |
| 产物体积 | 组件库 chunk 实测 gzip 体积；**预算在试点后由评审定**，不是先验拍一个数字 | `npm run build` 后读 `dist/assets/*.js` gzip；`du -b` |
| 表格密度可控性 | 用例页 10 列在 1440 与 1920 下：行高、表头粘性、横向滚动只在表格容器内 | 两宽度截图 + `check_i18n.py` 长度检查 |

评审结论只能由大师给出，四种结果：① Naive UI 通过；② Element Plus 通过；③ 两版都不达标 → 回退自建方案
（原 v1.0 §2.2 保留为回退路径）；④ 补充试点后再评。
