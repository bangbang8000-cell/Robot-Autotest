## 1. 现状核查（不是猜的）

### 1.1 主题：只有一套暗色，且色值散落

```
frontend/src/styles/main.css:2-9  :root { --bg:#0f1720; --side:#131c26; --panel:#1a2634; ... }
```

- `main.css` 内 **35 处硬编码 hex**，其中 `#22303f`（边框）出现 9 次、`#2b3a4b` 出现 5 次，都不在变量里。
- `views/` 与 `components/` 内另有 **65 处硬编码 hex**（告警底色 `#3a2c14`、成功底 `#2c5a40` 等）。
- 无 `data-theme`、无 `prefers-color-scheme`、无切换入口、无持久化。
- `index.html` 无内联主题脚本 → 直接加切换会出现**首屏闪白**。

**结论**：不是「加一套亮色变量」就完事。**必须先 token 化，把 100 处硬编码清零**，否则亮色下会出现黑块、
深色边框、看不清的告警条——这类缺陷最容易被当成「没做完」而不是「做错了」。

### 1.2 批量操作：一处都没有

全仓对 `checkbox` 的搜索结果只有 3 处，且都不是列表选择：

| 位置 | 用途 |
|---|---|
| `PlansView.vue:459` | 表单里的单个布尔开关 |
| `ReportDetailView.vue:636` | 「对比模式」开关 |
| `ReportDetailView.vue:564` | 选择某条用例看趋势 |

列表页（用例 / 资产 / 报告 / 运行 / 用户）**零勾选、零全选、零批量条**，全部只能一行一行点。
用例审批尤其明显：`POST /cases/{id}/review` 一次一条，审 50 条要点 50 次刷新 50 次。

### 1.3 国际化：前端 420 键对齐，但三个口子在漏

| 口子 | 证据 | 影响 |
|---|---|---|
| 硬编码中文 | `EditorView.vue` 24 处（`>加载中…<`、`'可编辑'`、`'地址缺少 projectId 或 path 参数'`） | 英文界面直接见中文 |
| 枚举裸显 | `CasesView.vue:307` `{{ c.reviewStatus }}` 显示 `draft/pending/approved/rejected` | 中文界面见英文 |
| **服务端错误文案** | `new BusinessException(...)` 共 **271 处，其中 213 处带中文裸文案**（如「凭据名称已存在：」） | 英文界面下所有业务报错仍是中文 |

语言包本身 `zh-CN.ts` / `en-US.ts` 各 420 行、键数一致，**基线是好的**；缺的是「守门」——没有脚本拦
「新增中文硬编码」和「新增键只写一边」。

### 1.4 项目中心：后端已有八成，前端缺一环，资产模型要改

**已经有的**（不用重做）：

- 表：`project` / `project_member(owner|member|viewer)` / `app_user` / `role` / `user_role`
- 接口：项目 CRUD + **成员增删改**（`ProjectController` 72~95 行）、用户 CRUD + 重置口令、角色 CRUD
- 路径：资产 / 用例 / 执行 / 报告全部 `/api/projects/{projectId}/...`，`bindProject` 强制成员校验
- 前端：`ProjectPicker` 切换器 + `auth.projectId` 落 localStorage

**缺的 / 要改的**：

1. **成员管理没有界面**。`AdminView.vue` 只有「用户 / 项目 / 角色」三块，**没有「项目成员」**。
   后端接口齐了但用户点不到 —— 这就是「多用户多项目灵活组合」目前不可用的真实原因。
2. **权限双轨没有明文规则**。`AccessControlService.effectiveRole()` 实际口径是
   「全局 ADMIN 优先 → 项目成员角色 → 全局最高角色」，但 PRD 没写。用户看到「我是工程师」却进不去某项目会困惑。
3. **资产是严格项目私有**。`device.project_id NOT NULL` + `uk_device_project_name(project_id,name)`；
   `DeviceRepositoryJdbc` 里 15 处 `project_id` 条件。同一台物理机在三个项目里 = 三份记录，改 IP 要改三处。
4. **用例其实已经和资产解耦**（`test_case` 不持有 `device_id`，DUT 在执行时才绑定），这是优点，
   但目前**没有任何约束保证它不被破坏**——需要一条回归判据钉住。

## 3. 主题设计

### 3.1 三层结构

```
primitives（只在主题块内出现）  →  semantic（组件只用这层）  →  组件
--gray-950 / --gray-50              --bg / --panel / --border      .card { background: var(--panel) }
--blue-500 / --red-500              --accent / --fail
```

**硬规则**：`frontend/src/views/**` 与 `components/**` 内**不允许出现 hex 色值**，只允许 `var(--*)`。
由 `tools/check_colors.py` 守门（新增脚本，见 §9 验收）。

### 3.2 语义变量清单（本版定稿）

| 变量 | 用途 | 暗色 | 亮色 |
|---|---|---|---|
| `--bg` | 页面底 | `#0f1720` | `#f5f7fa` |
| `--side` | 侧栏底 | `#131c26` | `#ffffff` |
| `--panel` | 卡片/表格底 | `#1a2634` | `#ffffff` |
| `--panel-2` | 表头/次级块 | `#141f2b` | `#f0f3f7` |
| `--border` | 常规描边 | `#22303f` | `#dde3ea` |
| `--border-strong` | 聚焦/强调描边 | `#2b3a4b` | `#c3ccd8` |
| `--text` | 正文 | `#e6edf3` | `#1a2230` |
| `--text-muted` | 辅助文字 | `#8b9bb0` | `#5b6b7d` |
| `--accent` | 主色 | `#3fa7ff` | `#0b63c5` |
| `--ok` / `--fail` | 成功 / 失败 | `#46c07a` / `#e05555` | `#1a7f4b` / `#c62828` |
| `--ok-weak` / `--fail-weak` / `--warn-weak` | 状态底色 | 深底 | 浅底 |

> 亮色不是把暗色「反过来」。`--accent` 必须加深（`#3fa7ff` 在白底上对比度只有 2.1:1，达不到 4.5:1）。

### 3.3 切换与持久化

- 三态 `themeMode: 'system' | 'light' | 'dark'`，存 `localStorage.theme_mode`。
- `resolvedTheme` = `themeMode === 'system' ? matchMedia('(prefers-color-scheme: light)').matches ? 'light' : 'dark' : themeMode`。
- 应用到 `<html data-theme="light|dark">`；**system 模式下监听 `matchMedia` change**，OS 切换即时跟。
- 切换入口：侧栏底部「◐ 主题」按钮，循环三态，`aria-label` + `title` 说明当前态。
- **防闪烁**：`index.html` 内联 8 行脚本，在 Vue 挂载前根据 localStorage / matchMedia 设好 `data-theme`。
- **跨设备**：新增 `user_preference(user_id, pref_key, pref_value)`，`theme_mode` 与 `locale` 都存这里；
  登录后拉一次覆盖本地。未登录（登录页）只用本地。

### 3.4 对比度下限（可机检）

正文 ≥ 4.5:1，辅助文字 ≥ 3:1，状态色（成功/失败）对其底色 ≥ 3:1。
`tools/check_contrast.py` 读两套变量算 WCAG 比值，低于下限即失败退出。

## 4. 批量选择与批量操作

### 4.1 通用选择模型

`frontend/src/composables/useSelection.ts`：

```ts
useSelection<T>({ items, keyOf })
// 返回：selectedIds: Set<string>, count, isAll, isIndeterminate,
//       toggle(id), toggleAllOnPage(), clear(), selectAllMatching(total)
```

**三条硬规则**（最容易做错的地方）：

1. **默认只选当前页**。表头勾选框 = 「本页全选」，不是「全部筛选结果全选」。
2. 需要「全部 N 条」时必须**二次确认**，并且 `N > 200` 直接拒绝并提示「请先缩小筛选范围」。
3. **翻页保留选择**（以 id 集合为准），批量条显示「已选 37 条（跨页 3 页）」，并提供「清空选择」。

`SelectionBar.vue`：选择数 > 0 时吸附在列表上方；`aria-live="polite"` 播报结果；
操作完成后**默认清空**，除非有失败条目（失败项保留选中，方便重试）。

### 4.2 用例批量（首批）

| 操作 | 后端 action | 前置状态校验 | 权限 |
|---|---|---|---|
| 提交评审 | `submit` | 仅 `draft` / `rejected` | `CASE:UPDATE` |
| 通过 | `approve` | 仅 `pending` | `CASE:UPDATE` + 非本人提交（同一人自审需 ADMIN） |
| 驳回 | `reject` | 仅 `pending`，必须带意见 | 同上 |
| 改优先级 | `setPriority` | 无 | `CASE:UPDATE` |
| 改技术域 | `setDomain` | 无 | `CASE:UPDATE` |
| 删除 | `delete` | 已 `approved` 的不允许批删，只能先驳回 | `CASE:DELETE` |

### 4.3 批量接口契约（统一）

```
POST /api/projects/{projectId}/cases/batch
{ "action": "approve", "ids": [1,2,3], "comment": "批量评审通过" }

200 {
  "total": 3, "succeeded": 2, "failed": 1,
  "results": [
    { "id": 1, "ok": true },
    { "id": 2, "ok": true },
    { "id": 3, "ok": false, "code": "CONFLICT", "message": "当前状态不可提交评审：approved" }
  ]
}
```

**四条契约硬规则**：

1. **部分失败仍返回 200**——整体非 200 只在「ids 为空 / 超过 200 条 / action 未知」时出现（400）。
2. **不做整批事务**。一条坏就全回滚会让用户白点，且无法知道哪条坏。逐条独立，各自事务。
3. **逐条审计**：每条一次 `audit_log`，带 `batch=<batchId>`，能回答「谁批量删了这 50 条」。
4. **删除按影响行数判定**：`DELETE ... WHERE id=? AND project_id=?` 影响 0 行 → 该条 `ok:false, code:NOT_FOUND`，
   不因为「别处已删」把整批判失败。

### 4.4 其余列表的接入方式

`UX-02` 只交付组件 + 用例。`UX-02b`（后续）按同一模板接资产（批量停用/删除）、报告（批量导出/清理）、
用户（批量启用/停用）。**不一次做完**，理由见 §8。

## 5. 国际化一致

### 5.1 三类文本的处置口径（本版定稿）

| 类别 | 例子 | 处置 |
|---|---|---|
| 界面文案 | 按钮、表头、提示、空态 | **必须**走 i18n，中英各一份 |
| 枚举值 | `draft` / `P0` / `owner` / `finished` | **必须**经 `statusLabels.ts` 映射，不裸显 |
| 业务内容 | 用例标题与步骤、设备名、项目名、报告正文、失败原因 | **不翻译**，按原样显示（大师明确放宽） |
| 服务端报错 | 「凭据名称已存在：」 | 前端按 `ErrorCode.name` 映射；原文折叠为「详情」 |

### 5.2 服务端错误本地化（最大的口子）

`ErrorCode` 已经带有稳定的英文 `name`（`INVALID_ARGUMENT` / `FORBIDDEN` / `CONFLICT`…），
**这正好可以当 i18n key 用**，不需要改 213 处异常文案。

```
前端：t(`error.${codeName}`, { detail: message })
zh: error.CONFLICT = '冲突：{detail}'
en: error.CONFLICT = 'Conflict: {detail}'
```

例外：`detail` 仍是中文（来自服务端）。**分两步**：

- **本版（UX-03）**：错误码映射 + `detail` 折叠到「显示详情」里。英文界面主文案是英文，中文细节按需展开。
  这是**诚实的部分解**，不假装已完全本地化。
- **后续（UX-03b）**：服务端改为「错误码 + 结构化参数」（如 `code=CONFLICT, params={field:'name', value:'xxx'}`），
  前端完全本地化。271 处逐个改，单独排期。

> 写清楚这一点的原因：如果不写，验收时会出现「英文界面还有个中文括号」的扯皮；
> 写了，它就是**已知边界**而不是缺陷。

### 5.3 守门脚本

`tools/check_i18n.py` 三项检查，任一失败即非零退出：

1. `zh-CN.ts` 与 `en-US.ts` 键集合**完全相等**（缺键 / 多键都报）。
2. `views/` `components/` 模板里 `>中文<` 出现即报（白名单：语言包本身、用例内容插槽）。
3. 值相同的键报警（`zh` 与 `en` 值一模一样的键，通常是漏译）。

### 5.4 格式本地化

日期时间用 `Intl.DateTimeFormat(locale)`；数字用 `Intl.NumberFormat`；
**耗时与文件大小**单独做 `formatDuration` / `formatBytes`（`1.5 s` / `2.3 MB` 而不是 `1500` / `2411724`）。

### 5.5 产品命名统一（NAM-01，2026-11-04 追加）

**定名**：英文 `AIDC AutoTest` ｜ 中文 `AIDC自动化测试`。

**只改「用户看得见的名字」，工程标识一个都不动**——这条边界是本包唯一的风险点，
必须先划清楚，否则改名会变成一次部署事故。

| 类别 | 处置 | 具体 |
|---|---|---|
| 界面显示名 | **改** | 登录页标题、侧栏品牌位、浏览器 `<title>`、报告页眉与导出物页眉 |
| 语言包 | **改** | `app.title`：`zh-CN` → `AIDC自动化测试`；`en-US` → `AIDC AutoTest` |
| 文档标题 | **改** | `README.md` 首行、各版本 PRD/DEV-PLAN 首页抬头（只在「产品名」位置，不改正文里的历史表述） |
| 仓库名 | **不改** | 仍是 `Robot-Autotest`：改了所有人要重配 remote 与 CI |
| Maven `artifactId` / jar 名 | **不改** | `robot-autotest-backend`：改了启动脚本、systemd、备份路径全断 |
| npm `name` / 目录名 | **不改** | `robot-autotest-frontend` |
| Java 包名 | **不改** | `com.qa.autotest.*` |
| 数据库名 / 表名 / 前缀 | **不改** | `robot_dev` / `robot_it` |
| 环境变量前缀 | **不改** | 平台触发端已按现有名字配置 |

**口径**：产品对外叫「AIDC自动化测试 / AIDC AutoTest」，代码里叫 `robot-autotest`。
两者不冲突，**不允许为了「统一」去改代码标识**——收益为零，破坏面很大。

**一处容易漏的地方**：`frontend/index.html` 的 `<title>` 是**静态写死**的，不随语言切换。
本包顺带修掉：用 `document.title` 在语言/路由变化时同步（`t('app.title')`），否则英文界面浏览器标签仍是中文名。

## 6. 项目中心与资产池

### 6.1 以项目为中心的三层结构

```
平台层（跨项目）    用户 · 角色 · 资产池（设备/链路/凭据）· 审计
   ↓ 成员关系 + 引用
项目层              项目 · 成员 · 用例 · 用例集 · 执行计划 · 运行 · 报告
   ↓ 结果
报告层              通过率 · 趋势 · 失败 Top · 未覆盖 · 导出
```

**一条设计约束**（写进 PRD 作为不退化项）：**用例不绑定具体设备**。
用例只声明「需要什么能力/环境」（`capability` / `domain_tag` / `precondition`），
具体 DUT 由执行时从「本项目可见资产」里选。这样同一批用例能在不同实验室复用，这是解耦的真正含义。
`AST-05` 要加一条回归判据：`test_case` 表**不得**新增 `device_id` 一类的列。

### 6.2 资产池 schema 改造（AST-05）

```sql
-- V6_x__asset_pool.sql（示意，实施时按现有迁移序号续）
ALTER TABLE device      ADD COLUMN owner_scope VARCHAR(16) NOT NULL DEFAULT 'PROJECT'
                        COMMENT 'PROJECT=项目私有 PLATFORM=平台共享';
ALTER TABLE link        ADD COLUMN owner_scope VARCHAR(16) NOT NULL DEFAULT 'PROJECT';
ALTER TABLE credential  ADD COLUMN owner_scope VARCHAR(16) NOT NULL DEFAULT 'PROJECT';

ALTER TABLE device      MODIFY project_id BIGINT NULL;
ALTER TABLE link        MODIFY project_id BIGINT NULL;
ALTER TABLE credential  MODIFY project_id BIGINT NULL;

CREATE TABLE project_asset (
  id         BIGINT      NOT NULL AUTO_INCREMENT,
  project_id BIGINT      NOT NULL,
  asset_type VARCHAR(16) NOT NULL COMMENT 'DEVICE/LINK/CREDENTIAL',
  asset_id   BIGINT      NOT NULL,
  alias      VARCHAR(128) NULL COMMENT '项目内别名，为空则用资产名',
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  created_by BIGINT      NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_project_asset (project_id, asset_type, asset_id),
  CONSTRAINT fk_project_asset_project FOREIGN KEY (project_id) REFERENCES `project` (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目对平台资产的引用';
```

**存量迁移（关键，不能只改表结构）**：

1. 每个存量 `device` / `link` / `credential` 按原 `project_id` 在 `project_asset` 插一条引用 →
   **升级后每个项目看到的东西和升级前完全一样**（这一步不做就会出现「升级后资产全没了」）。
2. `owner_scope` 全部留 `PROJECT`；是否转 `PLATFORM` 由用户在界面上手动「共享到平台」决定，
   **不自动把私有资产变成共享**（否则是越权）。
3. 唯一键：`uk_device_project_name(project_id, name)` 在 `project_id` 为 NULL 时失效（MySQL 唯一索引允许多 NULL），
   平台级资产改用 `uk_device_serial(serial_no)` 保证唯一；项目内重名由 `project_asset.alias` 唯一性保证。

**查询口径**（统一收在一处，禁止各仓储手写）：

```sql
-- 本项目可见设备
FROM device d
LEFT JOIN project_asset pa
       ON pa.asset_id = d.id AND pa.asset_type = 'DEVICE' AND pa.project_id = :pid
WHERE d.project_id = :pid
   OR (d.owner_scope = 'PLATFORM' AND pa.id IS NOT NULL)
```

> 这条 SQL 必须做成单一常量（如 `AssetScopeSql.DEVICE_VISIBLE`），由架构测试守住「资产仓储不得自拼 project_id 条件」。
> 23 个仓储里有 8 个涉及资产/执行，靠人记一定会漏。

### 6.3 引用保护（PRJ-03）

| 动作 | 规则 |
|---|---|
| 删除平台资产 | 有任一项目引用 → **409**，提示「被 N 个项目引用，请先解除引用」 |
| 删除项目私有资产 | 允许；同时清 `project_asset` 中本项目引用 |
| 项目内「移除资产」 | 只删 `project_asset` 行，不动物资本体 |
| 平台资产转为项目私有 | 需先解除其他项目引用（ADMIN 操作，二次确认） |
| 项目删除 | 级联删 `project_asset`，**不删**平台资产 |

### 6.4 成员与权限口径（PRJ-01）

**明文规则（写进 PRD，代码与文档同一口径）**：

| 场景 | 有效角色 |
|---|---|
| 全局 `admin` | 全平台全部动作（含跨项目） |
| 项目成员 | **以 `project_member.member_role` 为准**（`owner` > `member` > `viewer`） |
| 非成员但有全局角色 | 进不去项目（`bindProject` 403）；全局角色只决定平台级能力 |
| 项目 `owner` | 不可被他人移除，不可降级；离职/停用需先转移 owner |

前端要做的（后端接口已齐，纯补界面）：

- 管理页新增「项目成员」区块：选项目 → 成员表格（用户 / 项目角色 / 加入时间）→ 添加 / 改角色 / 移除。
- 项目切换器补「我的项目」分组 + 「无项目」引导（联系管理员加入）。
- 被停用的用户，成员关系保留但登录被拒（已在 `AuthService`），前端成员表要标「已停用」。

### 6.5 报告结果导向（PRJ-04）

项目页首屏（在 OVW-01 四区之上补「结果视角」）：

- 最近 5 份报告（运行号 / 通过率 / 失败数 / 导出入口）
- 失败用例 Top 10（按最近 30 天失败次数排序）
- 未被执行过的用例数（覆盖率缺口，这是「用例资产有没有被用起来」的唯一硬指标）
- 趋势：通过率折线（按天/按运行），点击进入报告详情

新增只读接口 `GET /api/projects/{projectId}/report-digest?days=30`，不改表结构。

## 7. 权限与隔离（不能倒退的部分）

- 所有新增接口一律 `/api/projects/{projectId}/...`，`bindProject` 强制成员校验。
- 批量接口的每一条都要带 `project_id` 条件，**不能**先按 id 批量取再过滤（会出现部分越权读）。
- 资产池的「平台资产」对**非成员不可见**：即便 `owner_scope=PLATFORM`，也必须有 `project_asset` 引用才能看到。
  否则共享池会变成跨项目数据泄露。
- `TenantGuard` 元测试要覆盖新表 `project_asset`（无 `project_id` 的查询必须报错）。

## 8. 不做什么（明确划线）

| 不做 | 理由 |
|---|---|
| 自定义主题配色 / 三套以上主题 | 两套 + 跟随系统已覆盖真实场景；配色自由会让对比度校验失效 |
| 批量异步任务队列 | 200 条同步足够（单条 < 30 ms），引入队列是为不存在的规模付成本 |
| 跨项目共享**用例** | 用例绑技术域与实验室能力，跨项目共享会制造「跑不了却被引用」的脏数据；先只共享资产 |
| 字段级权限 / 数据脱敏分级 | 属 v1.0 HRD 范围，现在做会拖住主线 |
| SSO / LDAP | 外部依赖，未列入本阶段需求 |
| 服务端错误全量结构化（UX-03b） | 271 处，独立排期；本版只做错误码映射 + 详情折叠 |
