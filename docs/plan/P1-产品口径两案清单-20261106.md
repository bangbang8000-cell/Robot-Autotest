## 5. PRJ-01 · 两处基线问题（WBS #67）

**缺口原文**：① `project.owner_id` 为 NULL 且 `member_role` 还是 V1 的 `owner` → 保护无对象可保护，
已做一次性数据归一（SQL 见 `docs/evidence/v0.2/prj01/README.md` §六，**其他环境需同样回填**）；
② 原 `ProjectMember` 无 `displayName` / `enabled`（本包已补）。当前 Flyway 到 `V7_6` / 47 表。

| 项 | 案 A · 实现 | 案 B · 显式降级 |
|---|---|---|
| 做法 | 把归一 SQL 纳入 Flyway：新增 `V7_7__project_owner_backfill.sql`（+ down），所有环境 migrate 自动回填；补 `ProjectOwnerBackfillIT` | 保留一次性 SQL 手册，在运维手册与 WBS 明确「**其他环境需人工执行**」，并加启动期自检告警（owner_id 为 NULL 时告警） |
| 影响面 | 新增迁移版本（当前 `V7_6` / 47 表，`db-audit` 期望值需同步）；`SchemaIT` / 回滚链需复跑 | 不改库结构；多环境靠人工，漏执行则 owner 保护静默失效 |
| 验收判据 | 全新库 migrate 后 `owner_id` 非 NULL、owner 移除 / 降级返回 **409**、`db-undo` 可回滚、47 表审计不变 | 手册条目 + 启动告警 + 现有 4 条边界用例全绿 |

**学徒推荐**：**案 A**（一次性 SQL 在多环境极易漏，属真实基线风险），**但必须先获大师授权新增迁移版本**；
未授权前一律按案 B 出文档，不动库。
