## 1. 结论先行（六条）

1. **"要开发的功能"基本没有了，剩下的是"要证明的功能"。** 130 包五态为 **124 已完成 / 0 待验 / 6 待现场**，
   W1–W7 功能面已铺到 v1.0；但 v2.0 的 67 条 TC 实际是 **PASS 15 / PARTIAL 42 / NOT-RUN 10**。
   PARTIAL ≠ 通过，G8 十条判定**一条未动**。
2. **最该先做的不是新功能，是把 42 条 PARTIAL 转 PASS。** 二轮收口（`66c1fec`）已证明方法有效：
   9 个包靠"真实 HTTP / 真实 Chrome / 真库并发 / 真实 WS"从 `待验` 清零，并抓出 **7 个"单测全绿"的真缺陷**。
3. **发现一处被误记为"待现场 / 需 G4"的本机缺口：pytest 运行时根本没装。**
   `config/pytest-venv.yml` 写着 `created_by: scripts/setup-pytest-venv.sh`，但**该脚本不存在**，
   `~/venvs/pytest-kernel` 不存在，全机三处 Python（`~/rf-stack/.venv`、系统 `python3`、`~/miniconda3`）
   **均无 pytest**。所以 TC-20/22/23/24/32/36/37/38 与 M1–M10 的 NOT-RUN/PARTIAL，
   根因是**环境准备少做一步**，不是 G4 未判过、也不是缺外部样本。
4. **G8 第 1 条名义满足、实质不满足**：W1–W7 在 WBS 全 `已完成`，但 G8 第 2/4/5/6/7/8/9/10 条的
   证据来源正是那 42+10 条 TC。**不能靠五态过关。**
5. **一处文档回写缺口（流程第 ⑦ 道欠账）**：`v2.0-platform/05-TEST-REPORT.md` 仍把 TC-64 记 `NOT-RUN`、
   §1 记 NOT-RUN 10，而 `UIX-04` 已在二轮实跑 **16/16 截图**并转 `已完成`——测试报告没跟上事实。
6. **规划里没有"v2.1 功能清单"**：v3.0 只到 **B9 / G8**，之后是运营期 Q1–Q4 的**主题级**表述
   （稳定 / 覆盖 / 提效 / 扩展）。所以"下一批做什么"要先定性质：
   **收口版（把 v2.0 判过并 GA）还是扩功能版（v2.1）**。本文原建议**先收口**——
   **该建议已于 2026-11-06 被拍板推翻：定为扩功能版，见 §6 第 2 条。**
