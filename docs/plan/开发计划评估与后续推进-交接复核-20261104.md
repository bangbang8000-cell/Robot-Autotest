> `Server accepts key` 再下结论；这与交接文档坑 11「别只看配置下结论」是同一类，但方向相反——

## 4. v0.2 的 38 条孤儿 FR：逐条分类结论

**判据**：`tools/check_release_docs.py` 采用「TEST-PLAN 中出现该 FR 编号」的宽松匹配。
分类脚本逐条取 PRD 原文与 TEST-PLAN 章节比对，结论如下。

| 类别 | 条数 | 范围 | 处置 |
|---|---:|---|---|
| **A 类：已有 TC 与实测结果，仅缺 FR 编号** | **37** | `FR-v0.2-25~39`、`41~42`、`44~63` | 在 §12 / §13.1~13.9 各章节标题下补一行「对应 PRD：FR-...」，**不新增、不改写任何用例** |
| **B 类：本版范围外，实质未验** | **1** | `FR-v0.2-40`（UX-02b / WBS #71，P2） | 在 §13.11 显式登记「本版不实现、不编 TC，机检按编号匹配会算覆盖但**实质未验**，G2 不得据此判过」 |
| **C 类：真无用例** | **0** | — | 无需补 TC |

**结论**：`FAIL` 是**文档回写遗漏**，不是测试缺口。按大师「先逐条分类再定」的选择，
没有把形式缺口当需求缺口返工；补链后机检 `FAIL 0 / WARN 0`。
**同时留了一句防假绿的话**：机检的宽松匹配会把 B 类也算覆盖，故在测试计划里显式标注，
避免下一任 Agent 或 G2 核验人误读。

### 4.2 secret-scan：从「假红」到「带自检的真绿」

三处命中都是变量引用（`--password="$DB_PASSWORD"`、`DB_PASSWORD="${DB_PASSWORD:-}"`），
正则把 `${...}` 当明文。修法两步：

1. 正则收紧为「引号内首字符不是 `$`」的字面量，并把正则抽成 `REGEX` 变量供两处共用；
2. **双向自检**：真明文 `password="hunter2-selftest"` 必须仍被拦、变量引用必须不被误判；
   另排除脚本自身（否则自检样例被自己的 `git grep` 扫到，出现自咬式假红）。

破坏性验证（`python3 /tmp/verify_secret_scan.py`，一次性脚本）：
正常态 `exit=0` → 往 `scripts/db-common.sh` 注入 `password="RealSecret-2026"` → `exit=1` 且命中该行
→ 还原 → `exit=0`，文件字节数完全一致。随后 `bash scripts/lint.sh` → **`[lint] PASS`**。
