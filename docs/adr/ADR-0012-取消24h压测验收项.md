# ADR-0012 · 取消 24h 连续压测与观察窗，稳定性验收改为试点迭代记录

- **状态**：**待批准（事后补记）** — 变更已实际生效，本条 ADR 补的是「谁批、为什么、替代什么」
- **日期**：2026-11-04（决定日 2026-11-03，提交 `d3fae4c`）
- **决策人**：**大师（待签署）** ｜ 记录：学徒（AI）
- **约束范围**：v1.0（G7）稳定性验收；后续版本的能力阶梯基线

## 背景

`HRD-03` 原定验收为三项硬指标：

| 原验收项 | 原判据 | 出处 |
|---|---|---|
| 连续压测时长 | 24 小时不间断 | `docs/release/v1.0-ga/DEV-PLAN.md` HRD-03 |
| 内存增长 | RSS 增幅 < 20% | 同上 |
| 观察窗 | 压测后设观察窗，指标回稳 | 同上 |

2026-11-03 提交 `d3fae4c` 已取消这三项，把验收改为「小型试点项目持续迭代验证 + 运维手册可执行」，
但**只改了 DEV-PLAN 与 `WBS-STATUS` 的一行备注，没有 ADR**。按规划 §1.2 规矩 6，
**下调 KPI 属 AI 不得自行决定的事项**；缺口必须补上，否则后续任何「指标调不动就先取消」都可以援引此例。

## 决定

1. **取消**「24 小时连续压测 + RSS < 20% + 观察窗」三项作为验收门槛。
2. **改为**：小型试点项目**持续迭代验证**——每轮记录 `崩溃 / 重启 / 内存趋势 / 连接数 / 运行结果`，
   作为优化输入；**不设时长与轮次硬门槛**，评价由每轮迭代评审给出。
3. `scripts/stability-24h.sh` **保留脚本名**（`--duration` 可调），降级为「按需采样工具」，不再是门禁证据。
4. 规划 §2.3 的「一周连续运行成功率 ≥99%」**保留不动**（R0 阶段指标，由试点迭代记录作证）。

## 理由

| 理由 | 说明 |
|---|---|
| **合成压测测不出真问题** | 24h 空转压测主要暴露内存泄漏；而本平台的真实风险在「pabot 子进程树残留」「租约不释放」「报告目录膨胀」——这三类只在**真实用例、真实 DUT、真实产物**下出现，合成负载覆盖不到 |
| **体量与收益不匹配** | 平台是自用小规模（数十台设备、单机部署），24h 合成压测的边际信息量低于同样时间投入在真机链路上的收益 |
| **替代证据更强** | 试点迭代每轮都产生「崩溃次数 / 重启次数 / 内存曲线」，是**带真实负载**的纵向数据；比一次性 24h 的横截面更有说服力 |
| **硬门槛会产生假动作** | 设 RSS<20% 硬门槛会诱导「到点重启进程」这类凑数操作，把指标做绿而不是把问题解决 |

## 后果

- **正面**：验收不再依赖「跑一整夜」；证据来自真实使用，转运营的判据更实。
- **负面（必须承认）**：**失去了「连续 24 小时无泄漏」这一条明确证据**。若将来出现长跑内存问题，本 ADR 是第一个要被翻出来看的地方。
- **补偿措施**：① `window-stats.sql` 保留，试点每轮出一次统计；② 内存趋势进入迭代评审必看项；③ 若任一轮出现 RSS 单调上升，**自动升级为 P1 缺陷**，并按原 24h 脚本补测。
- **不可援引为通例**：本条只针对「24h 合成压测」一项。其他 KPI（4 并发 2.5x、metadata 100%、越权 0 例、回滚 RTO≤30 分钟）**均不得援引本条下调**。
