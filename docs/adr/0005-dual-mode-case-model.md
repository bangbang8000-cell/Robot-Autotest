# ADR-0005 · 双模用例模型（台账 + 脚本，内容即真源）

- **状态**：已采纳（CAS-01 评审签发，2026-11-02）
- **日期**：2026-11-02
- **决策人**：大师（评审会）、silence
- **约束范围**：v0.2 起全部用例域、v0.3 编辑器、v0.4 执行、v0.5 报告

> 编号说明：v0.2 DEV-PLAN 原写 `ADR-0004`，但 `0004` 已由 CI runner 决策占用；
> 本条改为 `0005`，并同步订正 v0.2 计划里的引用（ADR 编号不复用）。

## 背景

历史资产是 **461 条 Excel 台账**（编号 / 标题 / 分类 / 优先级 / 预置条件 / 步骤 / 预期 / 技术域），
其中只有少量会写成 Robot Framework 脚本。与此同时，v0.3 的编辑器需要一个可读写、
可版本化的脚本文档载体；v0.4 执行需要把脚本落盘后交给 RF。

三方约束合起来要求同一个模型同时容纳「人工台账」与「可执行脚本」，且不能让两者互相拖死：

- 台账必须能独立存在（461 条里绝大多数短期没有脚本）；
- 脚本必须能挂多条台账（数据驱动一脚本多用例）；
- 编辑器与执行必须读同一份内容，不能一份存结构化 AST、一份存文本。

基线报告 §11.2 与风险项 R3 明确指出：先写 CRUD 再定模型，等于用代码替评审做决定。

## 选项

| 选项 | 优点 | 代价 | 为什么不选 |
|---|---|---|---|
| ① 单一实体：用例表里直接存脚本内容 | 表少、查询简单 | 台账无脚本时字段空置；一脚本多台账只能复制；编辑器与台账字段耦合 | 461 条里多数无脚本，空置率过高 |
| ② 双实体但脚本存 AST（结构化） | 前端渲染方便 | 文本与 AST 双写必然不一致；RF 语法演进要改 AST schema | 双写不一致是长期债，直接否 |
| ③ **双实体：台账 `test_case` + 脚本 `robot_file.content` 唯一真源** | 各自独立演进；绑定关系弱耦合；编辑器/执行同源 | 绑定关系要额外表达（Tags / case_requirement）；脚本无结构索引，按内容检索靠 `sha256` 与全文 | **选它** |

## 决定

1. **台账是 `test_case`（含 `test_case_step`）**，编号 `case_code` 在**项目内唯一**（`uk_test_case_project_code`）。
   跨项目同名编号合法（不同项目各有一套 Excel）。
2. **脚本是 `robot_file`**，`content` 字符串是唯一真源；**不存 AST**。
   `content_sha256` 只用于变更检测，不作为内容本体。
3. **绑定关系**：`test_case` 不带 `robot_file_id` 外键。回链方式二选一：
   - RF 脚本 `[Tags]` 写 `case:<case_code>`；
   - `case_requirement` 记录 `req_key='robot_file'`、`req_value=<path>`。
   本版只实现台账与文件各自 CRUD，绑定查询在 v0.3 编辑器落地。
4. **版本层是快照表 `robot_file_version`**，不是 Git。每次保存生成一条快照；
   批量提交 Git 是异步的另一件事。**运行时读取 `robot_file.content`，不依赖 Git 工作区**。
5. **台账字段规范**：`priority ∈ {P0,P1,P2,P3}`；`review_status ∈ {draft,pending,approved,rejected}`；
   缺必填或编号格式不符时保存被拒并指出字段（不猜测、不静默截断）。

### 明确不做

- 不做 AST 持久化；
- 不做「台账 ↔ 脚本」强制一对一（1:0..1 或 1:N 都允许）；
- 不在本版做脚本解析（v0.3 EDT-01 起）。

## 后果

- 正面：461 条可先入库；编辑器有单一文本真源；执行落盘即所读内容；模型不再被 CRUD 反推。
- 负面：跨表一致性靠应用层保证（删台账不自动删脚本、改脚本不自动改台账标题）；
  绑定关系需要约定（Tags / case_requirement），查询要多一步。
- 触发复核：若 v0.3 编辑器需要「按结构检索脚本」（如按关键字查），
  应新增独立索引表，**而不是**把 AST 塞回 `robot_file`。
