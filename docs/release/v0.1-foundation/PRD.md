## 1. 版本定位

### 1.1 一句话

> **任何人（或任何 AI 会话）拿到仓库，30 分钟内能跑起一个空壳前后端和空库，并且知道「代码该放哪、测试该怎么跑」。**

### 1.2 这一版没有终端用户——必须说清楚

v0.1 是**开发体验（DX）版本**，不做任何业务功能。硬编一个「张工想录入设备」的用户故事是自欺欺人。它的用户是三类非终端角色：

| 角色 | 真实痛点 | 本版如何解决 |
|---|---|---|
| **接手开发的 AI 会话**（最主要） | 换个会话就不知道项目结构、构建命令、测试怎么跑，只能猜 | `AGENTS.md` + 目录约定 + 测试脚本，一次读完全掌握 |
| **运维 / 部署者**（silence） | 环境差异导致「我这儿能跑」 | 环境基线文档 + 配置注入规范，本地 WSL 与 Windows 开发机只差环境变量 |
| **后续版本**（v0.2~v1.0） | 每版重复解决同样的地基问题，越往后返工越贵 | schema、CI、分层规则一次定好，后面只加不改 |

**判断标准**：v0.1 的价值不在「有功能」，而在**后面 6 个版本能省多少重复劳动**。地基歪了，后面每一版都要还债。

### 1.3 不做什么

| 不做 | 原因 |
|---|---|
| 任何业务 CRUD（用户、设备、用例） | 那是 v0.2，本版只留空壳与表结构 |
| 前端真实页面 | 只做能跑通路由、i18n、请求封装的骨架 |
| 把 38 表字段写全 | 只写 DDL 骨架 + 主键外键索引，字段随版本用 Flyway 补（规划 §5.2 常见坑②） |
| 容器化 |按最小依赖约定不引入 Docker（基线报告 §4.2），本版及后续均走裸进程 |
| 生产级监控告警 | 进 v1.0 的 HRD-03 |

## 3. 非功能需求

| ID | 需求 | 目标 | 验收方式 |
|---|---|---|---|
| NFR-v0.1-01 | 冷启动耗时 | 干净 clone → 空壳可访问 **≤30 分钟**（含依赖下载） | 计时录屏，网络正常条件下 |
| NFR-v0.1-02 | 单次构建耗时 | 后端 `mvn -q package` ≤120 s；前端 `npm run build` ≤90 s | CI 日志取时间戳 |
| NFR-v0.1-03 | 无外部服务依赖 | 后端启动不连任何外网地址；前端不调第三方 API | CI 扫描 + 启动时抓包核对（对应 N13） |
| NFR-v0.1-04 | 仓库体积 | 单次提交 ≤5 MB，仓库总量 ≤50 MB（不含 `.git`） | `git count-objects -vH` |
| NFR-v0.1-05 | 可移植 | 本地 WSL（Ubuntu-24.04；Python 按 lock 重建）与 Windows 开发机均能构建 | 两端各跑一次 `make build` |

## 4. 关键设计约定（本版定，后续版本不得违反）

| 约定 | 内容 | 为什么在 v0.1 定 |
|---|---|---|
| 目录即边界 | 前端不得 import 后端代码；`packages/editor` 将来只依赖 `common` 类型 | 后补边界等于重构 |
| 一层一责 | `domain` 不碰框架注解；`api` 只做参数校验与转换 | ArchUnit 才有东西可拦 |
| 表按域前缀命名 | `app_user` / `device` / `test_case` / `execution_job` / `schedule` / `audit_log` | 38 张表必须有分组线索，否则半年后没人认得出 |
| 迁移单向 | 只允许新增 `V*.sql`，禁止改历史脚本 | 改历史脚本等于所有环境不一致 |
| 密钥不出环境 | 口令、token 一律环境变量，落盘即视为缺陷 | 凭据进 Git 是不可逆事故 |

## 5. 验收清单（G1 骨架门）

- [ ] `make bootstrap` 在干净 clone 上一次通过
- [ ] `mvn test` 绿，含 ArchUnit 规则
- [ ] **故意跨层引用被拦下**（现场演示，CI 变红）
- [ ] 空库 Flyway migrate → 38 表；undo → 0 表
- [ ] 前端 `npm run dev` 起得来，6 个路由可跳，i18n 可切
- [ ] PR 上 `lint` / `test` / `build` 三关独立可见
- [ ] 仓库内 grep 不到明文口令
- [ ] `AGENTS.md` 与 `docs/adr/` 就位
- [ ] 未参与实现的人按文档跑起一次（留录屏或时间戳）

## 6. 依赖、假设与风险

| 项 | 内容 |
|---|---|
| 前置 | G0 通过（runner 落点已定、双模模型与许可义务已评审） |
| 假设 | 本地 WSL 可 SSH；MySQL 8.0 已装且有建库权限；GitHub 仓库可推 |
| 风险 | **runner 落点未定**（P3）→ 本版会卡在 FR-v0.1-16，需大师决策：本地 WSL 裸进程 or 内网镜像仓（NAS）容器 |
| 风险 | 38 表 DDL 一次写全的冲动 → 明确只写骨架，字段随用随加 |
| 风险 | Testcontainers 不可用（按最小依赖约定不装 Docker）→ 已改为本机独立测试库，见 DEV-PLAN ADR-0002 |
