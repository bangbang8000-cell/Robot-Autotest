## 1. 版本定位

### 1.1 一句话

> **跑完就有报告看，十项 metadata 一条不缺，导出的 PDF 能直接发给客户，不用人工补一个字。**

### 1.2 这一版决定「平台能不能对外」

前四版做完，平台能编辑、能跑。但**能不能拿出去给客户看，取决于这一版**。判据很硬：

> 一份报告如果缺 `SW_BUILD` 或 `DUT`，它就不是证据，只是一张截图。

所以本版的验收标准不是「报告页面好看」，而是**「metadata 齐全率 100%，缺一项就不允许标可对外」**。这是平台存在的意义所在（对应 N13「有机整体」与基线报告 R5）。

### 1.3 本版三个不能妥协的点

| 点 | 具体要求 | 妥协的后果 |
|---|---|---|
| **metadata 十项门禁** | 十项齐全才允许标记「可对外」；缺项显式列出缺哪项 | 对外报告被质疑，追溯不了「哪台设备、哪个版本」 |
| **双列结果并置** | 历史结论与本轮结论**物理分列**，本轮没结论就显示「无」 | 历史通过冒充当轮通过——这是最恶劣的数据造假（不是故意的，但是结果一样） |
| **大字段不进库** | 日志落文件，库只存路径与 sha256 | 备份变慢、查询退化、库半年涨到几十 GB |

### 1.4 不做什么

| 不做 | 原因 |
|---|---|
| 报告模板可视化编辑器 | 首期用固定模板 + 变量；可配置模板进运营期 |
| 图表库全家桶 | 只做趋势折线 + 通过率饼图两张，够用 |
| 报告分享链接（对外公开） | 涉密风险；导出文件走邮件/IM |
| 自动生成「结论与建议」文字 | 那是 AI 分析（明确不在范围） |
| Word 精美排版 | Word 版是「可编辑的交付件」，排版从简，PDF 是正式版 |

## 2. 用户与场景

| 角色 | 场景 | 本版能力 |
|---|---|---|
| **测试工程师** | 跑完想知道哪条失败、失败在哪一步 | 套件树 → 用例 → 步骤 → 日志逐层下钻 |
| **测试工程师** | 这条用例上次也失败了吗 | 双列并置：历史 vs 本轮 |
| **测试负责人** | 这条链路这周的趋势 | 趋势图（通过率、耗时） |
| **大师 / 对外交付** | 给客户一份 PDF | 一键导出，metadata 页在最前 |
| 客户（间接） | 看结论，不关心平台 | PDF 自解释，不依赖登录 |

**核心场景（本版验收必走）**：

1. 张工跑完一次 4 并发的运行；
2. 打开报告 → 顶部显示运行概要（时间、设备、版本、并发度、通过/失败数）；
3. 左侧套件树，点一条失败用例 → 右侧步骤列表，失败步骤高亮，展开看日志原文；
4. 切到「对比」→ 同用例上次的结论在左列，本轮在右列，**本轮失败的项左列显示上次通过但明确标「历史」**；
5. 打开「metadata」→ 十项齐全，逐项可复制；
6. 点「导出 PDF」→ 30 秒内得到文件，**首页是 metadata 表**；
7. 若某次运行缺 `SW_BUILD` → 平台标记「不可对外」，导出按钮旁显示「缺 SW_BUILD，不能对外交付」。

### 3.3 双列结果并置（本版最容易被做坏的功能）

| ID | 需求 | 优先级 | 验收标准 | WBS |
|---|---|---|---|---|
| FR-v0.5-12 | 同一个用例，左列「历史」右列「本轮」，**物理分列不合并** | P0 | 两列标题明确标注「历史 / 本轮」与各自 run_id | RPT-03 |
| FR-v0.5-13 | 本轮无结论时右列显示「**无（本轮未执行）**」，不显示历史值 | P0 | 造一条本轮跳过的用例，右列为「无」并标灰 | RPT-03 |
| FR-v0.5-14 | 历史取「上一次同用例同环境」的运行，可手动切换基线 | P1 | 可切换基线 run，列标题随之更新；**手动基线允许跨环境，但必须显式标注（ADR-0008）** | RPT-03 |
| FR-v0.5-15 | 差异高亮：状态变化（过→失、失→过）标色并计数 | P0 | 概览显示「新失败 2 条 / 新通过 1 条」 | RPT-03 |
| FR-v0.5-16 | 不允许用历史值填充本轮空值（前端与后端都不得回填） | P0 | 接口返回中本轮缺失字段为 `null`，不是历史值 | RPT-03 |

> FR-v0.5-16 是本版唯一一条「**禁止做某件事**」的需求。历史冒充当轮是最难发现、后果最严重的错误——用户不会怀疑一个绿色的勾。

> **口径补记（2026-11-07，ADR-0008）**：自动基线仍限「同 DUT/LINK」，**手动基线允许跨 DUT/LINK**，
> 但结果必须带 `crossEnvironment=true` 与两侧 `DUT`/`LINK`，页面与导出件必须显示
> 「跨环境对比，仅用于排障参考，不得作为验收基线」。仍按 400 拒绝的只剩「基线不存在 / 不属于本项目」。
> 现状差异：代码当前仍对跨 DUT/LINK 的手动基线返回 400（`CompareService.java:166-183`），
> **实现项 W-B6-1~4 未落地前，对外一律按「暂不支持跨环境手动基线」表述**。

## 5. 交互约定

| 约定 | 内容 |
|---|---|
| 报告页不依赖登录也能看导出件 | 导出件是自解释文档 |
| 「可对外」用绿色徽标，「不可对外」用红色并写缺哪项 | 状态必须一眼可辨 |
| 双列并置的列标题必须带 run_id 与时间 | 防止看错基线 |
| 历史列用中性色，本轮列用强调色 | 让人默认看本轮 |
| 空态：「本轮未执行」而不是空白 | 空白会被误读为 0 |
| 清理入口只给管理员 | 破坏性操作 |

## 6. 验收清单（G5 报告门）

- [ ] 真实链路运行能出报告，十项 metadata **齐全率 100%**
- [ ] 缺一项时 `exportable=false`，且明确指出缺哪项
- [ ] 双列并置：本轮缺失显示「无」，**接口不返回历史值**
- [ ] 导出 PDF 首页十项可读，中文不乱码，用例数一致
- [ ] 1 万行日志页面不卡
- [ ] 清理 dry-run 与实际删除一致，三条保护规则生效
- [ ] 解析容错：损坏产物给明确错误，不产生半份报告
- [ ] 单 run 库记录 <1 MB
- [ ] 无 P0/P1 未关闭缺陷
