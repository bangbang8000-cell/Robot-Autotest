**文档编号** RA-REL-2026-007-PRD ｜ **版本** v1.0 ｜ **门禁** G7 上线门 → 持续迭代评审 ｜ **批次** B7 + B8（试点迭代）

## 1. 版本定位

### 1.1 一句话

> **敢把账号给别人用：权限查得清、出事退得回、日志追得到、有人守得住。**

### 1.2 为什么最后一版不叫「加功能」

前六版都在加能力。这一版**一个功能不加**，只回答三个问题：

| 问题 | 不回答的后果 |
|---|---|
| **权限有没有漏？** | 某天有人看到了不该看的项目数据，而你说不出「本来应该拦住」 |
| **出事能不能退？** | 上线第一天遇到阻塞缺陷，没有回滚路径，只能硬扛或停服 |
| **换人能接手吗？** | 平台只有一个人会用，那人一休假就全线瘫痪 |

所以本版的验收不是「功能演示」，是**演练与审计**：回滚演练的秒表、权限矩阵的每一格、审计日志的每一条、UAT 用户的每一句反馈。

### 1.3 上线门 + 持续迭代评审

| 段 | 内容 | 判定 |
|---|---|---|
| **G7 上线门** | 权限矩阵 + 审计 + 试点迭代 + 手册 + 回滚演练 + UAT 8 条 | 全绿才能对外开账号 |
| **迭代评审（持续）** | 小型试点项目按轮运行；每轮记录崩溃/重启/内存趋势/连接数，作为优化输入 | 每轮记录齐全 + 评审结论闭环才继续迭代/转运营（不设 ≥4 周、≥20 次硬判据） |

**不允许「先上线再说」**：G7 通过只是「可以给一小部分人用」；之后按轮持续迭代，每轮评审结论闭环才继续扩大范围，**不设固定观察窗**。

### 1.4 不做什么

| 不做 | 原因 |
|---|---|
| 新增业务功能 | 任何新需求进运营期待办池 |
| 性能优化（非达标的） | 只修达标线的，不做「更快」 |
| 高可用（双机、集群） | 单机足够 10 人使用；HA 是运营期评估项 |
| 渗透测试（第三方） | 内部权限矩阵 + 越权集覆盖；第三方渗透进运营期 |
| 迁移旧数据（除 461 条已迁） | 已完成 |

## 2. 用户与场景

| 角色 | 场景 | 本版给他的东西 |
|---|---|---|
| **管理员**（silence） | 新同事入职，要开账号并只给某个项目 | 明确角色，一键加成员，权限可校验 |
| **运维**（兼） | 半夜服务挂了，第二天要恢复 | 运维手册：重启、备份恢复、回滚，每步有命令 |
| **使用方**（张工团队） | 想知道「改了谁能查到」 | 审计日志可按人/资源/时间查 |
| **大师** | 要给别人演示平台能交付 | UAT 8 条场景全过 + 试点迭代记录 |
| **外部客户**（间接） | 收到 PDF 报告 | metadata 齐全、结论可回溯 |

**核心场景（本版验收必走）**：

1. 新同事入职：管理员建账号 → 分配「测试工程师」+ 加入项目 A → 该同事**看不到项目 B 的任何数据**；
2. 他误操作删了一个用例集 → 审计日志能查到「谁、何时、删了什么」；
3. 上线第 3 天发现一个阻塞缺陷 → 按手册回滚到上一版，**计时 ≤30 分钟**，数据不丢；
4. 用一个小型试点项目持续迭代：每轮记录运行结果、崩溃/重启、内存趋势与连接数，作为优化输入；
5. 运维新人按手册**独立**完成一次「备份 → 恢复」演练，全程不求助。

## 6. 依赖、假设与风险

| 项 | 内容 |
|---|---|
| 前置 | G2~G6 全部通过 |
| 环境 | 本地 WSL 单机（Ubuntu-24.04 + MySQL 8.0 @ `127.0.0.1:3306`，业务库 `robot_dev`；JDK 21；Node 22），执行内核 venv 按 lock 文件重建；常驻形态用 systemd 用户级 unit（需 `loginctl enable-linger`，否则重启后服务不起） |
| 假设 | 用户 ≤10 人；单机可满足 |
| 风险 | **试点迭代不能走过场**——每轮必须有真实运行与优化输入，否则评审无结论可写 |
| 风险 | 回滚演练失败（DB down 迁移有锁表/数据兼容问题）→ 必须真做，不能在文档里写「应该可以」 |
| 风险 | 关键人单点（P-R1）→ 知识转移 4 项必须由「不会的人」验证 |
| 风险 | 试点迭代期间出 P0 → 当期修复并回归，评审确认能力不倒退后再继续，不带病扩大范围 |
