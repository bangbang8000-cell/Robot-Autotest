## 1. 测试目标

### 1.1 一句话

> 证明「**改完还是原来那个意思**」，而不是「改完能存下去」。

### 1.2 三个不信任原则

| 不信任什么 | 为什么 | 对策 |
|---|---|---|
| 不信任编辑器自己说「解析成功」 | 它自己解析自己渲染，循环论证 | 用 Python `robot.api.get_model()` 做外部裁判 |
| 不信任 `dryrun` 通过 | dryrun 只证明语法能跑，不证明少了一个断言 | 必须同时做 AST 语义比对 |
| 不信任「样本全过」 | 样本太简单时 100% 通过没有信息量 | 样本里必须有 20 条语法边界（DEV-PLAN §5） |

### 1.3 不测什么

| 不测 | 原因 |
|---|---|
| 编辑器新增功能 | 本版不新增（PRD §1.4） |
| `.resource` / 变量文件编辑 | 不支持 |
| 多人并发编辑同一文件 | 不做合并，只测 409 冲突 |
| 上游 AI 面板、Repo 选择器 | 已裁掉 |
| 跨浏览器 | 只测 Chromium |

## 3. 往返保真测试（T1，本版核心）

### 3.1 三层裁判

| 层 | 判据 | 通过标准 |
|---|---|---|
| L1 可执行 | `robot --dryrun <往返后文件>` | 50/50 退出码 0 |
| L2 语义 | AST 归一化后比对（步骤关键词 + 参数 + Settings） | 50/50 无差异 |
| L3 人眼 | 抽 10 个样本逐行看注释/空行/可读性 | 无「不可接受的变化」 |

**L2 的归一化规则**（必须写死，否则每次判定不一样）：

- 比较项：`TestCase.name`、每个 `KEYWORD` 步骤的 `keyword` 与 `args`、`FOR/IF/TRY` 的结构与条件、`Settings` 段的键值、`Variables` 的键值。
- 忽略项：行号、缩进宽度、注释文本、空行数量、文件末尾换行。
- 字符串比对本归一化：去首尾空白、内部连续空白折为一个（RF 参数本身对多空格敏感，**只在比对时归一，不改文件**）。
