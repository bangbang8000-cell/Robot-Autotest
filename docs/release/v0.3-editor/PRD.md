## 1. 版本定位

### 1.1 一句话

> **用例第一次能「在平台里改」：三个视图看同一份内容，改完保存成版本，且改完还能跑。**

### 1.2 这一版的真正难点不是「能编辑」，是「改完还是原来那个意思」

普通编辑器只要「能打字」就算完成。这一版不是。因为平台的执行真源是 `.robot` 文本，任何一次保存都在改写即将被 `robot` 执行的文件。所以本版的验收标准只有一条硬的：

> **一条 20 步的用例，在三个视图里编辑保存后，`robot --dryrun` 能跑通，且步骤语义与手工写的一致。**

这句话拆成四个可测的事：**能解析（打开）、能保真（往返）、能执行（改完能跑）、不出错（只读不写）**。

### 1.3 为什么必须移植而不是新写

| 选项 | 工作量 | 风险 |
|---|---|---|
| 从零写一个 `.robot` 可视化编辑器 | 语法覆盖不全，写完要一年 | 高：RF 语法边角多（`FOR`/`IF`/`TRY`、内嵌参数、`[Tags]`、续行、转义） |
| 移植 RoboScope 的编辑器闭包 | 39 文件 / 15,946 行，改写 15 文件 / 2,604 行 | 中：**它已经被上游跑了一年多，语法覆盖是打过补丁的** |
| **本版选择：移植 + 去业务化** | 同上 | 中，但可控：改写点集中在 15 个文件 |

**代价要认**：移植意味着继承它的架构债（Vue Flow 的 4,233 行巨型组件、i18n 硬编码残留）。本版**不重构**，只做去业务化与接线（规划 §4.3 的 T1 不接受「顺便优化」）。

### 1.4 不做什么

| 不做 | 原因 |
|---|---|
| 新增编辑器功能（如「智能补全」「AI 生成步骤」） | 上游有什么用什么；新功能进运营期待办池 |
| 重构 `FlowEditor.vue`（4,233 行） | 拆分它风险大于收益，且会破坏 19 个上游测试 |
| 支持 `.resource` / `.yaml` 变量文件编辑 | 本版只编 `.robot`；变量文件走 v0.5 之后的待办 |
| 多人协同编辑 | 无需求，冲突解决成本远超收益 |
| Git 集成（提交、分支） | 版本快照在库里，Git 由 v0.6 的 PLN-03 处理 |

## 2. 用户与场景

| 角色 | 场景 | 本版给他的能力 |
|---|---|---|
| **测试工程师**（主） | 手里有一条台账，想把步骤写成能跑的脚本 | 从用例详情「新建脚本」→ 文本/表单视图编辑 → 保存 → 试跑 |
| **测试工程师** | 想看清一条已有脚本的逻辑分支 | 流程视图看拓扑，不改结构只读 |
| **测试负责人** | 复核别人改了什么 | 打开版本历史，逐版本 diff |
| **访客** | 只想看看用例长什么样 | 只读查看器，写操作 100% 拦截 |

**核心场景（本版验收必走）**：

1. 张工打开用例 `IM-FUN-001`，点「编写脚本」，得到一个带 metadata 十项的空模板；
2. 在**文本视图**粘贴一段 20 步的 `.robot`（含 `FOR` 循环与 `[Teardown]`）；
3. 切到**表单视图**，看到步骤被拆成「关键词 + 参数」结构，参数可编辑；
4. 切到**流程视图**，看到 `FOR` 被渲染成循环节点，改一个参数；
5. 切回文本视图，**原文其他部分一字未变**；
6. 保存 → 生成 v2 快照，diff 显示只有那一处改动；
7. 点「试跑」→ `robot --dryrun` 通过；
8. 把用户切成访客，同一页面所有输入框变只读，调接口写操作返回 403。

## 5. 交互约定

| 约定 | 内容 | 原因 |
|---|---|---|
| 默认打开文本视图 | 老手直接改文本最快 | 表单/流程是辅助，不是必经 |
| 三视图是同一份内容的不同投影 | 不做「表单专用字段」 | 一旦有专属字段就必然双写不一致 |
| 保存前必须解析通过 | 坏语法不许入库 | 库里存坏文件，执行域必然炸 |
| 只读时明确告知原因 | 「你没有该项目的编辑权限，联系管理员」 | 只禁用不解释会被当成 bug |
| 版本 diff 默认对比上一版 | 需要时可任选两版 | 90% 场景是看「刚改了什么」 |

## 7. 依赖、假设与风险

| 项 | 内容 |
|---|---|
| 前置 | G1 通过；v0.2 的 `robot_file` 表与用例详情页可用 |
| 上游源码 | `roboscope-src/rs-0.16.1`（6.95 MB / 1,212 条目），Apache-2.0 |
| 假设 | 19 个上游测试可无改动跑通（若必须改断言，需 ADR 说明为什么） |
| 风险 | **往返保真失败**（R1，本版最高）→ 见 DEV-PLAN §4 的独立裁判方法，不靠编辑器自证 |
| 风险 | `FlowEditor.vue` 4,233 行难以去业务化 → 允许「先注释掉业务逻辑再逐步删」，但必须留 TODO 清单 |
| 风险 | 许可义务遗漏（R6）→ EDT-08 单独成包，发布检查单为强制项 |
| 风险 | 品牌残留藏在构建产物里 → 扫描范围必须含 `dist/`，不只源码 |
