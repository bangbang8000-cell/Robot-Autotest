## 1. 版本定位

### 1.1 一句话

> **不用人点：每天到点自己跑，代码提交也自己跑，跑完结果自己回来。**

### 1.2 本版最大的隐藏需求：自动跑的运行也必须「可对外」

v0.5 立了一条规矩：metadata 十项齐全才允许标可对外。**定时任务与 CI 触发产生的 run 没有人在现场填 metadata**——如果计划配置里不带这些上下文，那么所有自动跑的运行都会是「不可对外」。

结果就是：平台自动化程度越高，可交付的报告越少。这是一个**必须在本版解决的结构性问题**，不是可选项。

| 项 | 谁提供 |
|---|---|
| `QA_PROJECT` | 计划所属项目 |
| `DUT` / `LINK` | 计划绑定的环境 |
| `SW_BUILD` | 计划配置里填，或从 CI 的 commit / tag 取 |
| `OPERATOR` | 计划创建人（或 `AUTO`） |
| `CASE_KIND` | 计划类型（smoke / regression / nightly） |
| `BASELINE` | 计划里指定基线 run，或留空（留空即「无基线」） |
| `CASE_ID` / `RUN_ID` / `STARTED_AT` | 运行时生成 |

**FR-v0.6-02 就是这条**：计划必须携带 metadata 上下文，并在创建 run 时注入。

### 1.3 不做什么

| 不做 | 原因 |
|---|---|
| 可视化 DAG 编辑器 | 依赖用简单「前置计划」表达即可，拖拽编辑器成本高收益低 |
| 失败自动重试整条计划 | 重试策略在 run 级（v0.4）；计划级重试会掩盖问题 |
| 通知（邮件 / IM / 企微） | 明确不在范围内；结果看报告页，后续进待办池 |
| 多执行节点调度 | 单机 |
| 替换 GitHub 做代码托管 | 内网镜像仓（NAS）裸库是权威源，GitHub 是协作面 |

## 2. 用户与场景

| 角色 | 场景 | 本版能力 |
|---|---|---|
| **测试工程师** | 每天早上 8 点自动跑 RDMA 冒烟，来公司先看结果 | 建 cron 计划，绑环境，跑完在运行记录里看 |
| 测试工程师 | 提交代码后想自动跑相关回归 | 配 CI 触发：push 到 `main` 就跑指定用例集 |
| 测试负责人 | 夜间全量回归要等冒烟跑完再跑 | 配依赖：夜间全量「前置」=冒烟计划 |
| 管理员 | 看哪些计划被谁启停过 | 计划变更留痕 |

**核心场景（本版验收必走）**：

1. 张工建计划「每日 RDMA 冒烟」：cron `0 0 8 * * ?`，时区 `Asia/Shanghai`，绑环境「RoCE 互通」，`SW_BUILD=SW-2026.11`，用例集「RDMA 冒烟」；
2. 保存后手动「立即试跑」一次，确认能出报告且**十项 metadata 齐全**；
3. 次日 08:00 自动触发，`trigger_type=schedule`，报告 `exportable=true`；
4. 张工再建「夜间全量」，��置依赖「每日 RDMA 冒烟」，冒烟失败则夜间全量**不启动**并标 `blocked`；
5. 研发 push 到 `main` → Actions 调平台接口 → 触发「提交回归」计划，`trigger_type=ci`，`SW_BUILD` 取自 commit sha 前 8 位；
6. 运行完成后，平台把结论回写为 commit status（GitHub 仓库）。

## 3. 功能需求

### 3.1 计划管理

| ID | 需求 | 优先级 | 验收标准 | WBS |
|---|---|---|---|---|
| FR-v0.6-01 | 计划 CRUD：名称、cron 表达式、时区、用例集、环境、并发度、启停开关 | P0 | 创建后可预览「接下来 5 次触发时间」 | PLN-01 |
| FR-v0.6-02 | **metadata 上下文**：计划携带 `QA_PROJECT`/`DUT`/`LINK`/`SW_BUILD`/`CASE_KIND`/`BASELINE`，触发时注入 run | P0 | 定时触发的 run 报告 `exportable=true` | PLN-01 |
| FR-v0.6-03 | cron 表达式校验与预览（含时区），非法表达式拒绝保存并说明 | P0 | `0 0 25 * * ?` 被拒并提示小时超范围 | PLN-01 |
| FR-v0.6-04 | 时区固定 `Asia/Shanghai`，不随服务器时区变化 | P0 | 改服务器 TZ 后触发时间不变 | PLN-01 |
| FR-v0.6-05 | 启停：停用的计划不触发，历史记录保留 | P0 | 停用后跨过一个触发点，无新 run | PLN-01 |
| FR-v0.6-06 | 「立即试跑」：用当前配置跑一次，`trigger_type=manual_trial` | P1 | 试跑不改变下次触发时间 | PLN-01 |
| FR-v0.6-07 | 计划的并发上限：同时最多 N 个（默认 1），超出则本次跳过并记录 | P0 | 上一轮未结束时新触发被标 `skipped(overlap)` | PLN-01 |
| FR-v0.6-08 | 错过触发的处理策略：错过 >5 分钟不补跑，记 `skipped(misfire)`；可在计划上改为「补跑一次」 | P0 | 停服 10 分钟后恢复，只有一次补跑（若配置） | PLN-01 |

### 3.2 依赖前置

| ID | 需求 | 优先级 | 验收标准 | WBS |

### 3.3 CI 触发

| ID | 需求 | 优先级 | 验收标准 | WBS |

## 4. 非功能需求

| ID | 需求 | 目标 | 验收方式 |
|---|---|---|---|
| NFR-v0.6-01 | 定时触发准确性 | 连续 7 天，触发时间偏差 ≤30 s，成功率 **100%** | 触发日志比对 |
| NFR-v0.6-02 | 重复触发 | 同一计划同一时刻只触发一次（多实例/重启场景） | 重启测试 + 日志 |

| NFR-v0.6-05 | 计划配置变更留痕 | 谁改了什么可查 | 审计 |

## 5. 交互与信息架构

| 约定 | 内容 |
|---|---|
| 「执行」菜单下「执行计划」页承载本版全部功能 | 不再新增一级菜单 |
| 计划卡片显示：下次触发时间、上次结论、是否启用 | 一眼看出状态 |
| 依赖关系用列表 + 简易缩进展示，不做图形 DAG | 成本收益不划算 |
| 触发记录（`schedule_trigger_log`）可查：为什么没跑 | 排障必需 |
| 「跳过」必须给原因（overlap / misfire / blocked / disabled） | 否则用户以为坏了 |

## 6. 验收清单（G6 计划门）

- [ ] 建一个 cron 计划，连续 7 天触发成功率 **100%**，偏差 ≤30 s
- [ ] 定时触发的 run **`exportable=true`**（metadata 由计划注入）
- [ ] 启停生效；停用后跨触发点无新 run
- [ ] 依赖：前置失败 → 后置 `blocked`；环检测拒绝保存
- [ ] CI 触发：push 能触发指定计划，同 commit 重放幂等
- [ ] GitHub commit status 能回写（若仓库已接入）
- [ ] 内网镜像仓（NAS）侧触发有本地记录，不虚报回写成功
- [ ] 停机恢复不雪崩（最多补 1 次）
- [ ] 无 P0/P1 未关闭缺陷

## 7. 依赖、假设与风险

| 项 | 内容 |
|---|---|
| 前置 | G5 通过（报告链路正确，否则自动化只会批量生产错数据） |
| 环境 | 本地 WSL 单机；自托管 runner；内网镜像仓（NAS）的 Container Manager 24.0.2 可用于 Gitea（若决定上） |
| 假设 | 单实例部署（不做集群），调度用数据库行锁防重复即可 |
| 风险 | **托管 runner 到不了内网**（R13）→ 必须自托管，文档要写死 |
| 风险 | 自动跑的 run 全不可对外 → FR-v0.6-02 是本版最高优先级，先做它再做 cron |
| 风险 | 内网镜像仓（NAS）无 API 被误认为「能回写」→ FR-v0.6-17 明确「只记录」，文档不得含糊 |
| 风险 | 定时任务堆积 → FR-v0.6-07 重叠跳过 + FR-v0.6-08 错过不补 |
