## 3. 越权测试集（IAM-05，20 条，本版核心）

### 3.1 设计原则

- **只走 HTTP，不调 Service**。注解拦不住的东西，只有真发请求才测得出来。
- **每条都要断言「拒绝」且「不泄露」**：403 而非 500，响应体不含资源标题、存在性、数量。
- **必须有正向对照**：同一请求换个合法身份要成功，否则「全拒」也能骗过测试。

## 4. 导入测试（461 条，本版最容易假通过的地方）

| ID | 用例 | 期望 |
|---|---|---|
| TC-v0.2-201 | 全量导入 | 461 条全部入库，失败 0 |
| TC-v0.2-202 | 字段对账 | 逐行 8 个字段与 Excel 比对，差异 0；抽查 20 条**逐字段**人眼核对 |
| TC-v0.2-203 | 幂等 | 同一文件再导一次：`COUNT(*)` 仍 461，`id` 不变，`updated_at` 更新 |
| TC-v0.2-204 | 坏数据整批回滚 | 461 条里改 3 条为非法优先级 → 提交后 `COUNT(*)` 仍为 0（不是 458） |
| TC-v0.2-205 | 报告准确性 | 上条场景的报告列出 3 行失败 + 行号 + 原因 + 其余 458 行「已通过校验」 |
| TC-v0.2-206 | 编号重复 | 两个项目各有一条 `IM-FUN-001` → 均成功（编号项目内唯一） |
| TC-v0.2-207 | 同项目编号重复 | 同项目内两条 `IM-FUN-001` → 后者更新前者，条数不增 |
| TC-v0.2-208 | 空步骤行 | 步骤列有多余空行 → 不产生空步骤记录 |
| TC-v0.2-209 | 超长字段 | 标题 300 字符 → 明确报错（超 255），不静默截断 |
| TC-v0.2-210 | 中文与特殊字符 | 含 emoji、全角、引号的内容 → 入库后字节一致（utf8mb4） |
| TC-v0.2-211 | 并发导入 | 两个用户同时导同一项目 → 一方成功一方明确失败或串行，**不产生重复** |

> **对账方法**：写一个一次性脚本 `scripts/reconcile_461.py`，读 Excel 与数据库，逐行逐字段 diff，输出差异清单。**不接受「导入成功 461 条」作为唯一证据**——条数对不代表内容对。

## 11. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 越权测试只测「拒绝」不测正向 | 全拒也能过，实际不可用 | 强制 TC-v0.2-121/122 |
| 导入只对条数不对字段 | 461 条进来但内容错位，半年后才发现 | 对账脚本 + 20 条人工抽样，写进退出标准 |
| 用真实口令做测试数据 | 凭据泄露 | 造数脚本只允许 `test-only-pwd` |
| 拦截器把复杂 SQL 改错 | 查询结果错但不报错 | 联表查询单独一组测试，结果与手写 SQL 比对 |
| 权限矩阵只测 4 个角色不测「无角色」 | 未分配项目的用户行为未定义 | 补一条「无项目成员身份」用例，期望 403 或空集 |
