## 2. 冻结结论

**一级菜单固定为 6 个，顺序不变：**

| 序号 | 菜单 | 路由 | 页面职责（v0.2 现状） |
|---:|---|---|---|
| 1 | 总览 | `/overview` | 环境与后端连通性自检；后续放待办、最近运行、失败趋势 |
| 2 | 资产 | `/assets` | 设备 / 端口 / 链路 / 凭据 / 技术域台账；项目级筛选 |
| 3 | 用例 | `/cases` | 用例台账（增删改查、评审流转、能力索引、Excel 导入）；v0.3 接三视图编辑器 |
| 4 | 执行 | `/runs` | v0.4 落地：队列、运行状态、实时日志、取消 / 重试 |
| 5 | 报告 | `/reports` | v0.5 落地：output.xml 解析、双列并置、趋势、导出 |
| 6 | 管理 | `/admin` | 用户 / 角色 / 项目；v1.0 扩审计查询与权限矩阵视图 |

**不进一级菜单的：**

- 登录页 `/login`：认证入口，不是导航项。
- 项目切换器：全局控件，常驻页面头部（`ProjectPicker`），不单独占菜单。
- 个人设置 / 改密：并入「管理」或头像菜单，v0.2 不做独立页。

## 3. 关键设计决定

| # | 决定 | 理由 |
|---|---|---|
| D1 | 菜单按**业务对象**分，不按操作类型（如不设"导入"独立菜单） | 导入是用例页的一个动作，独立成页会让对象与动作混层 |
| D2 | 资产与用例分成两个一级菜单 | 资产是环境事实，用例是测试资产；权限与生命周期不同 |
| D3 | 执行与报告分开 | 执行关注"正在发生"（队列 / 日志），报告关注"已经发生"（结果 / 导出），合并会让两种时间语义打架 |
| D4 | 管理独立一级菜单 | 用户 / 角色 / 项目是平台治理面，避免散落到各业务页 |
| D5 | 项目选择放全局头部，不作为菜单 | 所有业务页都在项目上下文内，做成菜单会导致"先选项目再进页面"的多余一跳 |
| D6 | 前端菜单常显，权限以服务端为准 | v0.2 只做体验层；按角色隐藏菜单留到 v1.0（HRD-01）统一做，避免两套规则 |

## 4. 变更控制

- 本纪要签字后，**增删一级菜单、调整顺序、改变路由语义**都必须新开 ADR，并在 `docs/plan/WBS-STATUS.md` 关联任务包。
- 页面内部布局、字段顺序、按钮位置不属于 IA，不走 ADR，按 `CONVENTIONS-frontend.md` 执行。
- 新增二级页面（如用例详情、运行详情）不改变一级 IA，无需 ADR，但要在本纪要附录登记路由。

## 6. 遗留与风险

1. **执行 / 报告两个菜单在 v0.2 仍是占位页**——IA 冻结的是"位置与职责"，不是"页面已实现"；实现随 v0.4 / v0.5。
2. 管理页当前所有登录用户可见，非管理员操作会被后端 403 拒绝；是否在 v1.0 前改为按角色隐藏，待 HRD-01 一并决定。
3. 移动端适配未在本次评审范围内；当前只保证桌面 1280 以上可用。
