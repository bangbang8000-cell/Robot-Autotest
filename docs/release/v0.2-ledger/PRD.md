## 1. 版本定位

### 1.1 一句话

> **平台第一次「有东西可查」：谁能用、有什么设备、有哪些用例，都能登录进去查到、筛出来、评审掉。**

### 1.2 这一版解决的真实痛点

| 痛点（现状） | 具体表现 | 本版如何解决 |
|---|---|---|
| **用例资产在 Excel 里** | 461 条散在多个 sheet，按技术域找一条要翻半天，改一条要发邮件通知三个人 | 入库存为**台账**，可按技术域/优先级/状态组合筛选；改动留版本 |
| **设备占用靠问人** | 「GPU01 的 mlx5_0 现在谁在用」只能群里问，经常撞车 | 设备-端口两级台账，端口是**可被引用的实体**（v0.4 租约的外键） |
| **凭据散在个人手里** | 每台 DUT 的口令在各自笔记里，人一走就断 | 加密存储 + 运行时注入，磁盘不见明文 |
| **多项目混在一起** | 8001 是单租户，A 项目的用例在 B 项目也能看到 | 行级 `org_id/project_id` 隔离，越权 0 例 |
| **不知道谁改了什么** | 用例被改了没人知道 | 关键写操作留痕（审计在 v1.0 补全查询，本版先落库） |

### 1.3 本版在 6 菜单上的进度

| 一级菜单 | v0.2 状态 | 说明 |
|---|---|---|
| 总览 | ✅ 真实化（OVW-01，待验） | 用例数 / 资产数 / 执行统计 / 近期执行四区，后端一次聚合；`FR-v0.2-25~29` |
| 资产 | ✅ 完成 | 设备与端口 / 环境与拓扑 / 凭据 三个二级页 |
| 用例 | ✅ 完成 | 用例库 / 用例集 / 导入与评估 / 能力索引 |
| 执行 | ⬜ 占位 | v0.4 |
| 报告 | ⬜ 占位 | v0.5 |
| 管理 | 🟡 补成员管理（PRJ-01，待验） | 用户与角色 / 项目 / **项目成员** / 审计（仅落库，查询在 v1.0） |

**横向能力（不进任何一级菜单，但每页都要用）**：亮/暗双主题（`UX-01`）、列表批量选择与操作（`UX-02`）、
中英一致性与产品命名（`UX-03` / `NAM-01`）。这三项没有独立页面，验收靠「每一页都不出问题」——
详见 §3.5~§3.7。**它们不是锦上添花**：主题与批量直接决定「白天能不能用」「50 条用例审多久」。

## 2. 用户与场景

| 角色 | 谁 | 关心什么 | 本版给他的能力 |
|---|---|---|---|
| **管理员** | silence | 谁能进、能看哪个项目 | 建用户、分角色、建项目、加成员 |
| **测试工程师**（主用户） | 实际使用者 | 录设备、录用例、快速找到要跑的那条 | 台账 CRUD + 组合筛选 + 批量导入 |
| **测试负责人** | 大师 | 覆盖够不够、用例质量如何 | 只读全量 + 评审状态流转 |
| **访客** | 外部/临时 | 看结果，不改东西 | 只读，且写操作被拦 |

**核心场景（一条走完才算本版合格）**：

1. 管理员建项目「RoCE 互通」，把张工加为测试工程师；
2. 张工录入 10 台设备（GPU01~GPU05、DUT-01~05），每台挂 2 个端口；
3. 张工配一条链路：`GPU01/mlx5_0 → 交换机 → DUT-01/mlx5_0`；
4. 张工导入 461 条用例台账，其中 38 条标 `domain=rdma`；
5. 张工在用例库筛 `domain=rdma AND priority=P0`，得到 12 条；
6. 他把这 12 条组成用例集「RDMA 冒烟」；
7. 负责人打开同一页面复核，看不到「RoCE 互通」以外的项目数据。

## 5. 交互与信息架构约定

| 约定 | 内容 | 原因 |
|---|---|---|
| 技术域不做导航 | 只做筛选标签与用例树分类轴 | 8001 的 13 菜单里技术域占 45%，是失控起点（基线报告 §6.6） |
| 一个功能一个入口 | 设备只在「资产/设备与端口」，不在别处重复入口 | 解决 8001 的 IA-2 问题 |
| 双列并置预留 | 用例库列表右侧预留「本轮结论」列（v0.5 填充） | 表结构先留位，避免后期改表 |
| 空态必须写清下一步 | 每个空列表给一句「你该先做什么」 | 新用户不知道从哪开始 |
| 危险操作二次确认 | 删除项目、删除用户、清空用例集 | 不可逆操作 |
